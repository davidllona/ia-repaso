Un bloque Transformer: atención y FFN, cada una con su atajo y su LayerNorm

La atención mezcla tokens, pero sola no es un Transformer. El bloque le añade un atajo (residual), una normalización por token y una pequeña red que procesa cada token: entra (n, d) y sale (n, d), así que se apilan.

Índice del módulo

Apilas 12 bloques y en cada uno la derivada del sub-bloque vale \(F' = 0{,}01\). Si quitas las conexiones residuales, ¿el gradiente llega casi entero al principio o desaparece?

Desaparece: \(0{,}01^{12} = 10^{-24}\). Con residual, \(y = x + F(x)\) tiene derivada \(1 + F'\) y queda \(1{,}01^{12} \approx 1{,}13\). El atajo es lo que permite apilar decenas de bloques, como en las ResNet.

Cuatro piezas que se repiten

  • x(n, d)
  • Atención+ x → LayerNorm
  • FFN+ x → LayerNorm
  • salida(n, d)
  • LayerNormalization normaliza cada token por separado: media 0 y desviación 1 con sus propios \(d\) números, y luego \(\gamma\) y \(\beta\) aprendidos. No depende del lote ni de la longitud; BatchNorm sí.
  • Conexión residual: se devuelve entrada + corrección, \(y = x + F(x)\). El gradiente pasa por el atajo con valor 1 y lo que había se conserva. Exige que \(x\) y \(F(x)\) tengan la misma forma.
  • FFN por posición: Dense(d_ff) + ReLU + Dense(d), con los mismos pesos para cada token. La atención mezcla entre tokens; la FFN procesa lo que cada uno recogió.
  • Post-LN o pre-LN: sumar y luego normalizar (artículo original, nuestro código) o normalizar antes (GPT-2, más estable en redes muy profundas).

Con este bloque se hacen el encoder (BERT, sin máscara), el decoder (GPT, máscara causal) y el encoder + decoder (T5, con cross-attention). En Keras se programa como keras.layers.Layer con call, get_config y @keras.saving.register_keras_serializable().

Con números: cuatro notas de una película

Ejemplo numérico

Un token con \(d = 4\): \(x = (1, 2, 3, 10)\), como cuatro notas de críticos a una película (inventadas).

  1. Media: \(\mu = 16/4 = 4\). Varianza: \((9 + 4 + 1 + 36)/4 = 12{,}5\); desviación 3,536.
  2. LayerNorm (\(\gamma = 1\), \(\beta = 0\)): \((-3, -2, -1, 6)/3{,}536 = (-0{,}849;\ -0{,}566;\ -0{,}283;\ 1{,}697)\).
  3. Parámetros de un bloque con \(d = 32\), \(d_{ff} = 64\): atención \(4224\) + FFN \(2\cdot 32\cdot 64 + 64 + 32 = 4192\) + dos LayerNorm \(128\) = 8.544.
Al generar texto, el modelo procesa un solo ejemplo cada vez (lote de 1). ¿Podría BatchNorm calcular su media por rasgo? ¿Y LayerNorm?

BatchNorm no: necesita muchos ejemplos del lote para su media por rasgo, y con 1 ejemplo (o rellenos y longitudes variables) sus estadísticas no sirven. LayerNorm sí: solo usa los números del propio token.

En tres líneas

  • Bloque = atención + residual + LayerNorm, y FFN (\(d \to d_{ff} \to d\)) + residual + LayerNorm.
  • Residual: el gradiente pasa con valor 1. LayerNorm: cada token se normaliza con sus propios números.
  • Entrada y salida \((n, d)\): se apila; BERT, GPT y T5 solo cambian la máscara y el cruce.

El bloque Transformer encoder, pieza a pieza

La atención mezcla tokens, pero sola no es un Transformer. ¿Qué más lleva un bloque, para qué sirve cada pieza y qué pasaría si la quitaras?

Un bloque tiene dos sub-bloques (atención y red feed-forward), cada uno rodeado de una conexión residual y una normalización. La entrada y la salida tienen la misma forma \((n, d_{model})\), así que se pueden apilar tantos bloques como quieras. Es el TransformerBlock que ya usaste en el proyecto del Curso 2; ahora vemos qué hace cada línea.

x ──┬──────────────► (+) ─► LayerNorm ──┬────────────► (+) ─► LayerNorm ─► salida
    │                  ▲                  │               ▲
    └─ MultiHeadAttention (x, x) ─────────┘               │
                                          └─ Dense(ff) ─► ReLU ─► Dense(d_model)

Versión «post-LN» (la del artículo original y la de nuestro código): suma y luego normaliza.

1 · LayerNormalization

Mantiene los números en una escala razonable a medida que atraviesan muchas capas (si no, tras 12 o 96 bloques los valores se disparan o se apagan y el entrenamiento se vuelve inestable). Normaliza cada token por separado: calcula la media \(\mu\) y la varianza \(\sigma^2\) de sus \(d_{model}\) números y los reescala:

\[ \operatorname{LN}(x)_j = \gamma_j\,\frac{x_j - \mu}{\sqrt{\sigma^2 + \varepsilon}} + \beta_j \]

\(\gamma\) y \(\beta\) son dos vectores de \(d_{model}\) números que se aprenden (empiezan en 1 y 0) para que la red pueda «deshacer» la normalización si le conviene; \(\varepsilon\) es un número minúsculo para no dividir entre 0 (en LayerNormalization vale 0.001 por defecto; nuestro bloque usa 1e-6).

Ejemplo numérico

Un token con \(d = 4\): \(x = (1, 2, 3, 10)\). Piensa en una película que recibe cuatro notas de 0 a 10 (cifras inventadas): tres críticos le ponen 1, 2 y 3 y uno le pone un 10. LayerNorm las pasa a una escala común.

  1. Media: \(\mu = (1+2+3+10)/4 = 4\).
  2. Varianza: \(((1-4)^2 + (2-4)^2 + (3-4)^2 + (10-4)^2)/4 = (9 + 4 + 1 + 36)/4 = 12{,}5\). Desviación: \(\sqrt{12{,}5} = 3{,}536\).
  3. Normalizado (con \(\gamma = 1\), \(\beta = 0\) y \(\varepsilon\) despreciable): \((-3,\,-2,\,-1,\,6)/3{,}536 = (-0{,}849;\ -0{,}566;\ -0{,}283;\ 1{,}697)\). Media 0 y desviación 1.

¿Por qué LayerNorm y no BatchNorm? BatchNorm calcula las estadísticas a lo largo del lote (una media por rasgo, mezclando ejemplos y tokens). Con secuencias de longitud variable, rellenos y lotes pequeños esas estadísticas son inestables, y en generación (un ejemplo cada vez) ni siquiera existen. LayerNorm usa solo los números del propio token: da igual el lote y la longitud.

2 · Conexión residual

En lugar de devolver solo lo que calcula el sub-bloque, se devuelve entrada + lo que calcula: \(y = x + F(x)\). Dos razones:

  • El camino directo. La derivada es \(\partial y/\partial x = 1 + F'(x)\): aunque \(F'\) sea casi 0, el gradiente pasa con valor 1. En 12 bloques con \(F' = 0{,}01\), el gradiente conserva \(1{,}01^{12} \approx 1{,}13\) en lugar de \(0{,}01^{12} = 10^{-24}\). Es el mismo truco que las ResNet y lo que permite apilar decenas de capas.
  • Lo que había se conserva. El sub-bloque solo tiene que aprender la corrección a la entrada, no reconstruirla entera: es como entregar el guion original más las notas de corrección, en lugar de reescribirlo desde cero.
Ojo

La suma exige que \(x\) y \(F(x)\) tengan la misma forma. Por eso la atención devuelve \(d_{model}\) números (gracias a \(W_O\)) y por eso la red feed-forward termina en Dense(d_model). Si cambias una de esas dimensiones, Keras protesta con un error de formas incompatibles al sumar.

3 · Red feed-forward por posición

Dos capas Dense con una ReLU en medio: \(\operatorname{FFN}(x) = W_2\,\max(0,\,W_1 x + b_1) + b_2\), que sube de \(d_{model}\) a \(d_{ff}\) (habitualmente \(4\,d_{model}\)) y vuelve a bajar. Se aplica a cada token por separado y con los mismos pesos (position-wise): la atención mezcla información entre tokens y la FFN procesa lo que cada token ha recogido. Equivale a dos convoluciones Conv1D de tamaño de kernel 1; algunos ejemplos de Keras la escriben así. Es donde vive la mayor parte de los parámetros del bloque (el 66 % cuando \(d_{ff} = 4d_{model}\)).

Post-LN y pre-LN

Dónde se coloca la normalización cambia el comportamiento. Post-LN (artículo original): x = LN(x + Sub(x)). Pre-LN (GPT-2 en adelante): x = x + Sub(LN(x)), que deja el «carril» residual sin tocar y entrena de forma más estable con modelos muy profundos (en pre-LN se añade una LayerNorm final después del último bloque). Nuestro código usa post-LN por ser el de los tutoriales de Keras.

Cuántos parámetros tiene un bloque

Con \(d = d_{model}\) y \(d_{ff}\): atención \(4d^2 + 4d\); FFN \(2\,d\,d_{ff} + d_{ff} + d\); dos LayerNorm \(4d\) (sus \(\gamma\) y \(\beta\)). Para \(d = 32\) y \(d_{ff} = 64\): \(4224 + 4192 + 128 = 8544\), justo lo que verás en el fragmento 11. Para BERT-base (\(d = 768\), \(d_{ff} = 3072\)) salen 7.087.872 por bloque y unos 85 millones los 12 bloques (el resto de sus ~110 millones son los embeddings de unas 30.000 piezas de vocabulario).

Encoder, decoder y la familia: BERT, GPT y compañía

Con este bloque se construyen las tres arquitecturas famosas, que solo se diferencian en la máscara y en cómo se entrenan:

MáscaraSe entrena para…Sirve para
Encoder (BERT)Ninguna: cada token ve a los de ambos ladosRellenar palabras tapadas («masked language model»): «Shrek es una [MASK] de animación» → «película»Entender texto: clasificar, extraer, buscar, medir similitud. También es lo que usaremos con series.
Decoder (GPT)Causal: cada token solo ve hacia atrásPredecir el token siguienteGenerar texto, código, etc. Es el que construiremos al final.
Encoder + decoder (Transformer original, T5)Encoder libre; decoder causal con cross-attention al encoderSecuencia → secuencia (traducir, resumir)Cuando la entrada y la salida son textos distintos.

«Entender» frente a «generar» es solo cuestión de la máscara: con la causal el modelo puede entrenarse con la frase entera de una vez y aun así no hacer trampa. Otros usos del mismo bloque: Vision Transformers (el «texto» son trozos de imagen), audio y, como verás ahora, series temporales.

10 · LayerNormalization: a mano, con Keras y comparada con BatchNormalization

Para qué sirve Comprobar que LayerNormalization hace la cuenta \((x-\mu)/\sqrt{\sigma^2+\varepsilon}\) token a token, y ver con números qué diferencia a BatchNormalization. Usa layers del fragmento 7.

v = np.array([[2., 4., 6., 8.], [10., 20., 30., 40.]], dtype="float32")

mu = v.mean(axis=-1, keepdims=True)
var = v.var(axis=-1, keepdims=True)
manual = (v - mu) / np.sqrt(var + 1e-3)

ln = layers.LayerNormalization(epsilon=1e-3)
print("LayerNorm a mano :\n", manual.round(3))
print("LayerNorm Keras  :\n", ln(v).numpy().round(3))
print("media y desv. de cada fila tras normalizar:", ln(v).numpy().mean(axis=-1).round(3), ln(v).numpy().std(axis=-1).round(3))

bn = layers.BatchNormalization(epsilon=1e-3)
sal = bn(v, training=True).numpy()
print("BatchNorm (por columna):\n", sal.round(3))
print("parámetros LayerNorm:", ln.count_params(), "(gamma y beta, uno por número del token)")

11 · Capas propias: PositionalEncoding y TransformerBlock

Para qué sirve Crear las dos capas que usaremos en el resto del módulo con keras.layers.Layer: la suma de la codificación sinusoidal y el bloque Transformer (atención + LayerNorm + FFN + residuales), y comprobar sus formas y parámetros. Usa np de los anteriores.

import keras
from keras import layers, ops

@keras.saving.register_keras_serializable(package="c3m3")
class PositionalEncoding(layers.Layer):
    def __init__(self, max_pasos, d_model, **kwargs):
        super().__init__(**kwargs)
        self.max_pasos, self.d_model = max_pasos, d_model
        pos = np.arange(max_pasos)[:, None]
        i = np.arange(d_model // 2)[None, :]
        angulos = pos / 10000 ** (2 * i / d_model)
        pe = np.zeros((max_pasos, d_model), dtype="float32")
        pe[:, 0::2], pe[:, 1::2] = np.sin(angulos), np.cos(angulos)
        self.pe = pe

    def call(self, x):
        pe = ops.convert_to_tensor(self.pe)
        return x + pe[: ops.shape(x)[1]]

    def get_config(self):
        return {**super().get_config(), "max_pasos": self.max_pasos, "d_model": self.d_model}

@keras.saving.register_keras_serializable(package="c3m3")
class TransformerBlock(layers.Layer):
    def __init__(self, d_model, num_heads, ff_dim, dropout=0.1, causal=False, **kwargs):
        super().__init__(**kwargs)
        self.d_model, self.num_heads, self.ff_dim = d_model, num_heads, ff_dim
        self.dropout, self.causal = dropout, causal
        self.att = layers.MultiHeadAttention(num_heads=num_heads, key_dim=d_model // num_heads)
        self.ffn = keras.Sequential([layers.Dense(ff_dim, activation="relu"), layers.Dense(d_model)])
        self.norm1 = layers.LayerNormalization(epsilon=1e-6)
        self.norm2 = layers.LayerNormalization(epsilon=1e-6)
        self.drop = layers.Dropout(dropout)

    def call(self, x, training=False):
        a = self.att(x, x, use_causal_mask=self.causal)
        x = self.norm1(x + self.drop(a, training=training))
        f = self.ffn(x)
        return self.norm2(x + self.drop(f, training=training))

    def get_config(self):
        return {**super().get_config(), "d_model": self.d_model, "num_heads": self.num_heads,
                "ff_dim": self.ff_dim, "dropout": self.dropout, "causal": self.causal}

bloque = TransformerBlock(d_model=32, num_heads=4, ff_dim=64)
entrada = np.random.default_rng(0).normal(size=(2, 48, 32)).astype("float32")
salida = bloque(entrada)
print("entrada:", entrada.shape, "-> salida:", salida.shape)
print("parámetros del bloque:", bloque.count_params())
for capa in (bloque.att, bloque.ffn, bloque.norm1, bloque.norm2):
    print(f"  {type(capa).__name__:<22} {capa.count_params():>6}")
