Los cuatro casos de una clase

Para una clase concreta (por ejemplo, «Netflix avisa a un usuario de que un estreno le va a gustar») hay cuatro posibilidades:

  • TP (verdadero positivo): avisó y a la persona le gustó.
  • FP (falso positivo): avisó y no le gustó (falsa alarma).
  • FN (falso negativo): no avisó y le habría encantado (se escapó).
  • TN (verdadero negativo): no avisó y tampoco le gustaba.

Con ellos se definen las métricas que más se usan:

\[ \text{precisión}=\frac{TP}{TP+FP} \qquad \text{exhaustividad}=\frac{TP}{TP+FN} \qquad F_1=\frac{2\cdot\text{precisión}\cdot\text{exhaustividad}}{\text{precisión}+\text{exhaustividad}} \]

La precisión responde a «de las que marco como X, ¿cuántas lo son?» (de los avisos que mandas, ¿a cuántos les gusta de verdad?); la exhaustividad (recall) a «de las X que hay, ¿cuántas encuentro?» (de las películas que le gustarían, ¿de cuántas le avisas?); el F1 es la media armónica de ambas: solo es alto si las dos lo son. La exactitud (accuracy) es la fracción total de aciertos, \( (TP+TN)/N \).

  1. TP = 78 (imágenes de un 8 que se clasificaron como 8).
  2. FN = 20 + 1 + 7 + 39 = 67 (un 8 que se tomó por otra cifra).
  3. FP = 0 (ninguna otra cifra se clasificó como 8).
  4. Precisión = 78 / (78 + 0) = 1,000. Exhaustividad = 78 / (78 + 67) = 78 / 145 = 0,538.
  5. F1 = 2 · 1 · 0,538 / (1 + 0,538) = 0,700.

Cuando el modelo dice «8», casi siempre acierta; pero deja escapar casi la mitad de los 8 reales (67 de 145). La exactitud global (88 %) no deja ver este contraste. Es como un etiquetador que, cuando dice «comedia», casi siempre acierta, pero deja sin etiquetar casi la mitad de las comedias.

Lo que muestra el análisis de errores

El fragmento 20 saca el informe completo (classification_report) y las tres confusiones más frecuentes. Lo que cuenta:

  • El 8 se toma por un 9 (39 veces) y por un 5 (20 veces). Tiene sentido: el 8 comparte con el 9 el bucle superior y con el 5 buena parte del trazo. Y recuerda de dónde viene la base: se entrenó con las cifras 0 a 4, que no tienen ningún 8. Sus características congeladas no «conocen» la forma cerrada del 8 que lo separa de un 9.
  • Las demás cifras van bien: el 5, el 6 y el 7 tienen una exhaustividad de 0,974, 0,974 y 1,000, y el 9 de 0,913 (aunque con una precisión de 0,761 porque recibe los 8 mal clasificados). El fallo está concentrado en una cifra.
  • La confianza media del modelo es 0,96 cuando acierta y 0,73 cuando se equivoca: no sabe con certeza cuándo falla, pero duda más. Eso es lo que aprovechará el umbral de predecir().

Esa información dice qué hacer a continuación: conseguir más ejemplos de 8 (que es lo que falta) o descongelar más capas de la base para que aprenda esa forma. Mejorar «a ciegas» (más épocas, otra arquitectura) sin haber mirado los errores sería disparar en la oscuridad.

Ojo · el test se mira una vez, con la decisión ya tomada

Todo lo que has decidido (fases, learning rates, qué bloques descongelar) debe decidirse con la validación. Este análisis y las cifras del test son el informe final. Si, tras ver la matriz del test, cambias algo y vuelves a mirar el test, el test ha pasado a ser validación y ya no vale como examen final. En los fragmentos de este módulo se imprimen cifras de test para que veas el efecto de cada decisión, pero en un proyecto real las decisiones se toman con la validación.

probs = modelo_final.predict(XB_test, verbose=0)

print(pd.DataFrame(cm, index=["real " + n for n in nombres], columns=["pred " + n for n in nombres]).to_string())

fuera = cm.copy()

orden = np.dstack(np.unravel_index(np.argsort(-fuera, axis=None), fuera.shape))[0][:3]

confianza = probs.max(axis=1)
print(f"confianza media: aciertos {confianza[pred == yB_test].mean():.2f} | errores {confianza[pred != yB_test].mean():.2f}")
