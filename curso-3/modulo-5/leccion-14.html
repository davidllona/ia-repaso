El entrenamiento va mal y no sabes por dónde empezar. ¿Hay un orden razonable para diagnosticar?

De lo que ves a lo que debes probar
SíntomaCausa probableQué hacer
La pérdida es nan desde el primer loteLearning rate alto, pesos iniciales grandes, datos sin escalar, log(0)Baja \( \eta \) 10 veces, he_normal con ReLU, clipnorm=1.0, revisa los datos (gradientes)
La pérdida no se mueveLearning rate muy bajo, gradiente None (variable desconectada), sigmoides profundas, olvidar training=TrueComprueba los gradientes, sube \( \eta \), inicialización He, BatchNorm o atajos (bucle propio)
Entrenamiento baja, validación subeSobreajusteEarlyStopping, L2, Dropout, aumento de datos, más datos (regularización)
La pérdida oscila mucho\( \eta \) alto, lotes pequeños, ruido del gradienteBajar \( \eta \), ReduceLROnPlateau o coseno (schedules), lote mayor

La CPU/GPU está paradaCuello de botella de datosmap(num_parallel_calls=AUTOTUNE), cache, prefetch (tf.data)

datos       tf.data:  map -> cache -> shuffle -> batch -> prefetch
modelo      Dense/Conv con he_normal (ReLU); BatchNorm si es profundo
optimizador Adam(1e-3)  o  AdamW + coseno con warmup   (+ clipnorm=1.0 de cinturón)
callbacks   ModelCheckpoint + ReduceLROnPlateau + EarlyStopping (mismo monitor)

búsqueda    Keras Tuner (RandomSearch o Hyperband) sobre lr, capas, unidades
extras      precisión mixta solo si hay GPU adecuada; bucle propio solo si hace falta
