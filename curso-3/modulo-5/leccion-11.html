Un dataset puede ser demasiado grande para barajarlo entero. shuffle(buffer_size) hace esto: llena un buffer con los primeros buffer_size elementos; cada vez que hace falta uno, elige al azar uno de los del buffer, lo saca, y rellena el hueco con el siguiente elemento del dataset. tf.data: que el modelo no espere a los datos

Ves una película en streaming y cada poco se queda en «cargando…». Con mi entrenamiento pasa algo parecido: mi GPU (o mi CPU) está parada la mitad del tiempo y el entrenamiento va lento. Mi modelo es rápido; ¿dónde está el cuello de botella?

Analogía

El streaming de una película. El reproductor (el modelo) es rápido, pero necesita que le lleguen los trozos de vídeo (leer y transformar los datos). Si reproduce un trozo y se queda parado esperando a que se descargue el siguiente, ves el círculo de «cargando…». prefetch es el buffer de Netflix: va descargando los minutos siguientes mientras ves el actual. cache es tener la película ya descargada (modo sin conexión). map(num_parallel_calls=...) es descargar varios trozos a la vez desde varios servidores.

Una tf.data.Dataset es una secuencia de elementos y una cadena de transformaciones que se aplican de forma perezosa (cuando alguien pide el siguiente elemento) y que se ejecutan en el motor de TensorFlow, en paralelo con el entrenamiento. Los conceptos básicos, que usaste con image_dataset_from_directory en el módulo 2, aquí los vemos desde dentro (fragmento 13).

Crear y transformar

  • tf.data.Dataset.from_tensor_slices((X, y)): corta los tensores por la primera dimensión. Con diez datos de forma (1,) cada elemento es una pareja (x, y) de forma (1,); lo dice ds.element_spec.
  • .map(f): aplica f a cada elemento. f se traza como una tf.function: el fragmento cuenta cuántas veces ejecuta Python la función para diez elementos y la respuesta es 1. Un print o un contador dentro del map no ocurre por elemento. Con num_parallel_calls=tf.data.AUTOTUNE, varios elementos se procesan a la vez.
  • .cache(): guarda el resultado de lo anterior la primera vez que se recorre (en memoria, o en disco si le das una ruta). El fragmento lo mide con una función que sí ejecuta Python en cada elemento (tf.py_function): en 2 épocas de 10 elementos, 20 ejecuciones sin cache y 10 con cache.
  • .shuffle(buffer_size): baraja (ver más abajo).
  • .batch(n): agrupa n elementos. Con 10 elementos y batch(4) salen lotes de tamaño [4, 4, 2]; con drop_remainder=True, [4, 4] (el último incompleto se tira: útil para formas fijas, ver tf.function).
  • .prefetch(tf.data.AUTOTUNE): prepara lotes por adelantado mientras el modelo entrena.
  • .repeat(k) repite el dataset k veces y .take(n) se queda con los primeros n elementos: ds.repeat(2).take(13) da 13 elementos.

El orden de las etapas importa

Una receta que funciona casi siempre es:

ds.map(leer_y_preprocesar, num_parallel_calls=AUTOTUNE)   # lo caro y determinista
  .cache()                                                # se hace UNA vez
  .shuffle(buffer_size)                                   # barajar ejemplos, no lotes
  .map(aumentar_datos)                                    # lo aleatorio, DESPUÉS de la cache
  .batch(tamano_lote)
  .prefetch(tf.data.AUTOTUNE)                             # siempre lo último
  • cache después de lo caro y determinista, antes de lo aleatorio: si cacheas un RandomFlip, cada época vería la misma imagen volteada y se acaba el aumento de datos.
  • shuffle antes de batch: el fragmento lo demuestra con los diez números 0-9. shuffle → batch(5) da los lotes [4,9,1,0,7] y [3,5,2,8,6] (ejemplos mezclados); batch(5) → shuffle da [5,6,7,8,9] y [0,1,2,3,4]: solo reordenó los lotes enteros, cada lote sigue siendo la misma tanda.
  • prefetch al final, para solapar todo lo anterior con el entrenamiento.

shuffle(buffer_size): el barajado a medias

Un dataset puede ser demasiado grande para barajarlo entero. shuffle(buffer_size) hace esto: llena un buffer con los primeros buffer_size elementos; cada vez que hace falta uno, elige al azar uno de los del buffer, lo saca, y rellena el hueco con el siguiente elemento del dataset. Un elemento nunca puede salir más de buffer_size − 1 posiciones antes de su sitio original, así que si el buffer es pequeño y el dataset viene ordenado (todos los de una clase y luego los de otra), durante buena parte de la época el modelo ve casi solo la primera clase. Es como poner en «modo aleatorio» una lista de reproducción con las 30 películas de terror y luego las 30 de comedia, pero con una ventana minúscula: al principio solo saldría terror.

Por defecto, shuffle baraja de nuevo en cada época (reshuffle_each_iteration=True). Y cuando le pasas un Dataset a fit, el argumento shuffle=True de fit no hace nada con él: el barajado lo decide tu .shuffle(...).

Cuello de botella: ¿quién espera a quién?

Un pipeline son dos «carriles» que trabajan en cadena: el que prepara el lote (leer + map) y el que entrena con él. Sin prefetch van en serie y el tiempo por lote es la suma; con prefetch se solapan y el tiempo por lote es el del más lento de los dos.

Una vez que preparar un lote (30 ms) tarda menos que entrenar (50 ms), el modelo es el límite y más trucos de tf.data no ganan nada. Cada truco ataca una parte distinta: el paralelismo acorta la preparación, prefetch la esconde, cache la elimina a partir de la segunda época.

Pasarle el dataset a fit

Un Dataset ya trae las parejas (x, y) y el tamaño de lote, así que modelo.fit(pipeline, epochs=40) no lleva y= ni batch_size=; y validation_data=ds_val admite otro dataset. El fragmento 13 lo hace con un pipeline de diez datos (map → cache → shuffle → batch(4) → prefetch), cuya cardinality() es 3 lotes por época (\( \lceil 10/4\rceil=3 \)), y una neurona que aprende \( y=2x \): la pérdida baja de 0,1641 a 4,4·10⁻¹¹ en 40 épocas y predice 1,0 para \( x=1 \) (el 9 escalado).

Ojo · tres trampas de tf.data

(1) Efectos de Python en map (un print, un contador): solo ocurren al trazar. Para ejecutar Python de verdad hay que usar tf.py_function, que es lento y no se puede paralelizar bien. (2) cache() con aleatoriedad delante (shuffle o aumento antes de la cache): el resultado de la primera época se repite para siempre. (3) Un shuffle con un buffer_size mínimo sobre datos ordenados por clase: el modelo ve las clases «por turnos» y el entrenamiento oscila.

12 · Hyperband, BayesianOptimization y la clase HyperModel

Para qué sirve Define un HyperModel (que también busca el tamaño del lote), cuenta qué entrena Hyperband y deja que la optimización bayesiana elija cada intento mirando los anteriores.

import tempfile
import warnings
import numpy as np
import keras
import keras_tuner as kt
from sklearn.datasets import make_moons

warnings.filterwarnings("ignore")      # silencia avisos de TensorFlow/scikit-learn que ensucian la salida
keras.utils.set_random_seed(0)
X, y = make_moons(n_samples=600, noise=0.3, random_state=0)
X, y = X.astype("float32"), y.astype("float32")
Xe, ye, Xv, yv = X[:400], y[:400], X[400:], y[400:]

class MiHyperModel(kt.HyperModel):
    def build(self, hp):
        modelo = keras.Sequential([
            keras.Input(shape=(2,)),
            keras.layers.Dense(hp.Int("unidades", 8, 64, step=8), activation="relu"),
            keras.layers.Dense(1, activation="sigmoid"),
        ])
        modelo.compile(optimizer=keras.optimizers.Adam(hp.Float("lr", 1e-3, 1e-1, sampling="log")),
                       loss="binary_crossentropy", metrics=["accuracy"])
        return modelo

    def fit(self, hp, modelo, *args, **kwargs):          # también se pueden buscar hiperparámetros de fit
        return modelo.fit(*args, batch_size=hp.Choice("batch_size", [16, 32, 64]), **kwargs)

# --- Hyperband: muchos modelos con pocas épocas, y solo los mejores siguen ---
tuner = kt.Hyperband(MiHyperModel(), objective="val_accuracy", max_epochs=9, factor=3,
                     hyperband_iterations=1, seed=0, directory=tempfile.mkdtemp(),
                     project_name="hb", overwrite=True)
tuner.search(Xe, ye, validation_data=(Xv, yv), verbose=0)
filas = []
for t in tuner.oracle.trials.values():
    hp = t.hyperparameters.values
    filas.append((hp["tuner/bracket"], hp["tuner/round"], hp["tuner/initial_epoch"], hp["tuner/epochs"], t.score))
filas.sort(key=lambda f: (-f[0], f[1], f[2]))
print("Hyperband: trials totales =", len(filas))
print("bracket  ronda  modelos  épocas (de la a la)")
from collections import Counter
cuenta = Counter((b, r, ini, fin) for b, r, ini, fin, _ in filas)
for (b, r, ini, fin), n in sorted(cuenta.items(), key=lambda k: (-k[0][0], k[0][1])):
    print(f"{b:>7}{r:>7}{n:>9}   {ini} -> {fin}")
configuraciones = sum(n for (b, r, ini, fin), n in cuenta.items() if r == 0)
print("configuraciones distintas:", configuraciones, "| épocas entrenadas:", sum(fin - ini for _, _, ini, fin, _ in filas),
      "| entrenándolas todas hasta el final serían", configuraciones * 9)

# --- Optimización bayesiana: cada nuevo trial se elige mirando los anteriores ---
bayes = kt.BayesianOptimization(MiHyperModel(), objective="val_accuracy", max_trials=8,
                                num_initial_points=4, seed=0, directory=tempfile.mkdtemp(),
                                project_name="bo", overwrite=True)
bayes.search(Xe, ye, validation_data=(Xv, yv), epochs=10, verbose=0)
print()
print("Bayesiana: trial  unidades      lr  batch  val_accuracy")
for t in sorted(bayes.oracle.trials.values(), key=lambda t: int(t.trial_id)):
    hp = t.hyperparameters.values
    print(f"{t.trial_id:>16}{hp['unidades']:>9}{hp['lr']:>8.4f}{hp['batch_size']:>7}{t.score:>14.3f}")
