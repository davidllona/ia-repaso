tf.function traza una vez por firma y reutiliza el grafo

Decorar una función con @tf.function la convierte en una lista de reproducción: la primera llamada la monta (traza un grafo) y las siguientes solo le dan a play. Tu código Python solo se ejecuta al montarla.

Índice del módulo

Pones un print de Python dentro del call de tu modelo y entrenas 3 épocas de 4 lotes: 12 pasos. ¿Cuántas veces sale el texto?

Pocas, no 12 (en la versión usada, 3). Keras envuelve el paso de entrenamiento en una tf.function, y el código Python solo se ejecuta cuando se traza. Para ver valores en cada paso hay que usar tf.print, que forma parte del grafo.

Montar la lista una vez, reproducirla muchas

Con la ejecución inmediata (eager) cada operación se lanza desde Python una a una, como elegir a mano cada capítulo. Un grafo es una lista de reproducción que se encadena sola. tf.function hace esa conversión en tres pasos:

  1. Trazado. En la primera llamada ejecuta tu Python una vez con tensores simbólicos (solo forma y tipo, sin números) y anota cada operación de TensorFlow en un grafo.
  2. Ejecución. Las llamadas siguientes no ejecutan Python: ejecutan el grafo, más rápido y optimizable.
  3. Caché por firma. Cada grafo vale para una firma: tipo y forma de los tensores y valor de los argumentos de Python. Firma nueva → trazar otra vez (retracing).

De ahí sale todo lo demás: un print solo aparece al trazar y tf.print en cada llamada; pasar números de Python que cambian provoca un trazado por valor; y AutoGraph convierte tus if y for sobre tensores en tf.cond y tf.while_loop. En Keras casi nunca lo escribirás tú: fit, predict y evaluate ya lo usan.

Con números: seis llamadas, cuatro trazados

Ejemplo numérico
  1. f(tf.constant(1.0)): primera firma (float32, forma ()) → traza. Total 1.
  2. f(tf.constant(5.0)): misma firma → reutiliza. Total 1.
  3. f(tf.constant([1., 2.])): forma (2,) → traza. Total 2.
  4. f(3): entero de Python 3 → traza. Total 3.
  5. f(4): otro valor de Python → traza. Total 4.
  6. f(3) otra vez: ya estaba en la caché. Total 4.

Con una función que hace 100 operaciones pequeñas, el grafo da el mismo resultado (1,0201029) y es más de 3 veces más rápido.

Llamas a una tf.function dentro de un bucle con f(i) para i de 0 a 9.999, con enteros de Python. ¿Irá más rápida que sin decorar?

Probablemente más lenta. Cada entero distinto es una firma nueva: 10.000 trazados, y trazar es caro. Pasa tf.constant(i) (misma firma siempre) o fija la firma con input_signature. Si sospechas, cuenta con f.experimental_get_tracing_count().

En tres líneas

  • tf.function traza una vez por firma (forma, tipo y valor de Python) y reutiliza el grafo.
  • print sale solo al trazar; tf.print, en cada ejecución.
  • Pasa tensores, no números de Python que cambian, o habrá retracing.

tf.function: de Python a un grafo rápido

Con la ejecución inmediata cada operación se lanza desde Python una a una. ¿Cómo consigue entonces TensorFlow ser rápido? Y, de paso: ¿por qué un print dentro de tu modelo sale solo un par de veces durante fit, en lugar de una por lote?

Analogía

Ejecución inmediata es elegir a mano cada capítulo: terminas uno, vuelves al menú, buscas el siguiente y pulsas play, una vez por capítulo. Un grafo es montar una lista de reproducción: la preparas una vez y luego se encadena sola, sin que vuelvas a tocar nada. tf.function convierte tu función de Python en esa lista de reproducción. Montarla cuesta un rato (se hace solo la primera vez); después, reproducirla es barato.

Qué ocurre al llamar a una función decorada

Si decoras una función con @tf.function (o la envuelves con tf.function(f)), sucede esto:

  1. Trazado (tracing). En la primera llamada TensorFlow ejecuta tu código Python una vez, pero en lugar de números reales le pasa tensores simbólicos (marcadores con una forma y un tipo). Cada operación de TensorFlow que encuentra se anota en un grafo.
  2. Ejecución del grafo. A partir de ahí, las llamadas ya no ejecutan el código de Python: ejecutan el grafo anotado, que es mucho más rápido y puede optimizarse.
  3. Caché por firma. El grafo se guarda para una «firma»: el tipo y la forma de los tensores recibidos y el valor de los argumentos que no son tensores (un int de Python, por ejemplo). Si llamas con otra firma, hay que trazar otra vez y guardar otro grafo.

Haz esto. Pulsa, en este orden, f(tf.constant(1.0)), f(tf.constant(5.0)), f(tf.constant([1., 2.])) y los dos enteros de Python (f(3) y f(4)); luego repite f(3). Después pulsa «Vaciar la caché», elige «con input_signature» y repite las llamadas, incluida la de int32.

Fíjate en. Cada caja de la caché es un grafo y se crea una por firma nueva: otra forma, otro tipo o otro valor de Python. Los números de Python se «graban» dentro del grafo, así que cada valor distinto fuerza un trazado: eso es el retracing, y si ocurre en un bucle de miles de valores, el programa va más lento que sin tf.function. Con input_signature (tipo float32, cualquier longitud) hay un único grafo y el int32 se rechaza.

print frente a tf.print

Como el código Python solo se ejecuta al trazar, un print de Python dentro de una tf.function solo sale cuando se traza. En cambio tf.print es una operación de TensorFlow más: forma parte del grafo y sale en cada ejecución. Lo ves en la segunda mitad del fragmento 8: cuadrado(2.0) imprime el print de Python y el tf.print; cuadrado(3.0) reutiliza el grafo y solo imprime el tf.print.

Ojo · el print «que desaparece» en fit

Keras envuelve el paso de entrenamiento en una tf.function, así que un print dentro del método call de tu modelo se comporta como acabamos de ver. En el fragmento 10 hay 12 pasos de entrenamiento (3 épocas × 4 lotes) y el print aparece solo 3 veces, no 12; el número exacto depende de la versión, pero nunca será «uno por lote». En cambio, una llamada directa al modelo con datos (modelo(x)) se ejecuta con la ejecución inmediata: dos llamadas, dos print. Para depurar valores dentro de un modelo usa tf.print (o keras.ops y un callback), no print.

AutoGraph: tus if y for dentro del grafo

Un grafo no puede «ejecutar Python», así que ¿qué pasa con un if x > 0: cuando x es un tensor simbólico y no se sabe si será positivo? AutoGraph (se activa solo con tf.function) reescribe esos if, while y for a sus equivalentes de TensorFlow (tf.cond, tf.while_loop) cuando la condición depende de un tensor. En el fragmento 9:

  • La función signo tiene un if x > 0 con x tensor y funciona: signo(2.0) da «positivo» y signo(-2.0) «no positivo» (con el mismo grafo, sin reescribir nada).
  • for i in tf.range(n) (con tf.range, no range) se convierte en un bucle dentro del grafo: suma_hasta(5) da 10 (0+1+2+3+4) y suma_hasta(100) da 4950, y solo hubo un trazado para los dos.
  • input_signature=[tf.TensorSpec(shape=(None,), dtype=tf.float32)] declara de antemano qué entradas acepta («vectores de float32 de cualquier longitud»): se traza una sola vez y un tensor int32 da TypeError.

Y la razón de ser de todo esto, la velocidad: el fragmento mide una función que hace 100 pequeñas operaciones. El resultado es idéntico en modo inmediato y en grafo (1,0201029), pero el grafo es más de 3 veces más rápido (el fragmento lo comprueba con una comparación que sale True; no pegamos milisegundos porque cambian de un ordenador a otro).

Regla fácil

Tres hábitos con tf.function: (1) pasa tensores, no números de Python, como argumentos que cambian; (2) usa tf.print para ver valores y tf.range si el límite del bucle es un tensor; (3) si el programa va más lento de lo esperado, cuenta los trazados con f.experimental_get_tracing_count(): si crece sin parar, hay retracing. En Keras casi nunca la usarás explícitamente, porque fit, predict y evaluate ya lo hacen por ti.

8 · tf.function: trazado, caché de grafos y la diferencia entre print y tf.print

Para qué sirve Contar los trazados de una tf.function y ver con tus ojos cuándo se ejecuta el print de Python (solo al trazar) y cuándo el tf.print (siempre).

import tensorflow as tf

def doblar(x):
    print("  [Python] trazando con", x)
    return x * 2 + 1

f = tf.function(doblar)
print(f(tf.constant(1.0)).numpy())
print(f(tf.constant(5.0)).numpy())
print(f(tf.constant([1.0, 2.0])).numpy())
print(f(3).numpy())
print(f(4).numpy())
print(f(3).numpy())
print("trazados:", f.experimental_get_tracing_count())

@tf.function
def cuadrado(x):
    print("  [print] solo al trazar")
    tf.print("  [tf.print] x =", x)
    return x * x

print(cuadrado(tf.constant(2.0)).numpy())
print(cuadrado(tf.constant(3.0)).numpy())

9 · AutoGraph, input_signature y la ganancia de velocidad del grafo

Para qué sirve Ver cómo tf.function convierte if y for de Python en operaciones de grafo, cómo fijar la firma con input_signature y comprobar que el grafo es más rápido.

import time
import tensorflow as tf

@tf.function
def signo(x):
    if x > 0:
        return "positivo"
    return "no positivo"
print(signo(tf.constant(2.0)).numpy(), signo(tf.constant(-2.0)).numpy())

@tf.function
def suma_hasta(n):
    s = tf.constant(0)
    for i in tf.range(n):
        s += i
    return s
print(suma_hasta(tf.constant(5)).numpy(), suma_hasta(tf.constant(100)).numpy())
print("trazados de suma_hasta:", suma_hasta.experimental_get_tracing_count())

@tf.function(input_signature=[tf.TensorSpec(shape=(None,), dtype=tf.float32)])
def suma(x):
    return tf.reduce_sum(x)
print(suma(tf.constant([1., 2.])).numpy(), suma(tf.constant([1., 2., 3.])).numpy())
print("trazados de suma:", suma.experimental_get_tracing_count())
try:
    suma(tf.constant([1, 2, 3]))
except TypeError:
    print("TypeError: un tensor int32 no encaja en la firma float32")

def muchas(x):
    for _ in range(100):
        x = x * 1.0001 + 0.0001
    return x

muchas_grafo = tf.function(muchas)
x0 = tf.constant(1.0)
print("mismo resultado:", muchas(x0).numpy(), muchas_grafo(x0).numpy())

def tiempo(fn):
    fn(x0)
    t0 = time.perf_counter()
    for _ in range(50):
        fn(x0)
    return time.perf_counter() - t0

print("el grafo es más de 3 veces más rápido:", tiempo(muchas) > 3 * tiempo(muchas_grafo))
