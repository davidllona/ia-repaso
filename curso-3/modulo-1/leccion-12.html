Guardar y cargar modelos con piezas propias

Has entrenado un modelo con una capa tuya durante una hora. Lo guardas, cierras el cuaderno, lo abres mañana y load_model dice «Could not locate class». ¿Qué se guardó exactamente y qué falta?

Qué contiene un archivo .keras

modelo.save("modelo.keras") guarda un único archivo (en realidad un zip) con tres cosas: la arquitectura (config.json: qué capas hay y con qué hiperparámetros, es decir, el resultado de get_config de cada una), los pesos (model.weights.h5) y metadatos (metadata.json). Para cargarlo, Keras lee el config.json y tiene que reconstruir cada clase por su nombre: para Dense lo sabe, pero «CapaEscala» es un nombre que solo existe en tu código. De ahí los requisitos:

  • Toda capa o modelo personalizado debe tener get_config (con todos los argumentos de __init__), para que el JSON contenga lo necesario.
  • Keras debe poder encontrar la clase: o la registras con el decorador @keras.saving.register_keras_serializable(package="mi_paquete") sobre la clase, o se la das al cargar con custom_objects={"CapaEscala": CapaEscala}.

Ojo · lo que en Keras 3 ya no vale
  • model.save_weights("pesos.h5"): da ValueError: The filename must end in `.weights.h5`. En Keras 3 el archivo de pesos se llama algo.weights.h5.
  • model.save("carpeta") (el formato SavedModel de los cursos antiguos): da ValueError: Invalid filepath extension for saving. Please add either a `.keras` extension…. Para obtener un SavedModel (el formato de despliegue de TensorFlow) se usa modelo.export("carpeta").
  • model.save("modelo.h5") todavía funciona, pero es el formato legacy (antiguo, de Keras 2): conviene usar .keras. Keras lo considera formato antiguo (legacy); el fragmento 1 comprueba que todavía se puede guardar.

El problema de Lambda

Una capa Lambda con una función de Python (lambda t: t ** 2) guarda esa función como código. Cargar un archivo así significaría ejecutar el código que venga dentro, y si el archivo lo ha hecho otra persona, podría ser código malicioso. Por seguridad, Keras 3 se niega por defecto: «Requested the deserialization of a `Lambda` layer whose `function` is a Python lambda…» (último caso del fragmento 18). Si confías en el origen del archivo, load_model(ruta, safe_mode=False) lo permite. Mejor: escribe una capa propia con get_config, o registra la función con register_keras_serializable (en una prueba aparte, una Lambda con una función registrada cargó sin necesidad de safe_mode).

Modelos por subclases: get_config si __init__ tiene argumentos

El fragmento 19 guarda un modelo por subclases Mini(ocultas=5) de dos maneras: sin get_config y con él. Sin get_config, Keras no sabe que el modelo se creó con ocultas=5 y, al cargar, falla con «expected 2 variables, but received 0 variables» (esperaba pesos para 2 variables y no encontró nada). Con get_config que incluye ocultas, carga y las predicciones son idénticas.

Y para desplegar (llevar el modelo a otro entorno) el camino es modelo.export("carpeta"), que escribe un SavedModel de TensorFlow: saved_model.pb (el grafo), variables/ (los pesos), assets/ y fingerprint.pb. Se carga con tf.saved_model.load y se ejecuta con .serve(x), que reproduce al modelo (las salidas coinciden). Un SavedModel exportado sirve para ejecutar el modelo, no para seguir entrenándolo con Keras: para eso se usa .keras.

Regla fácil · guardar sin sorpresas

(1) Formato .keras para guardar y cargar con Keras; .weights.h5 si solo quieres los pesos; export() para desplegar. (2) Cada pieza propia: get_config con todos los argumentos de __init__ + @register_keras_serializable (o custom_objects). (3) Evita Lambda con funciones que quieras guardar. (4) Después de guardar, carga y compara predicciones con np.allclose, como hacen los fragmentos: es la única prueba de que todo se guardó.

16 · Una capa personalizada: CapaDensa con build, add_weight, call y get_config

Para qué sirve Escribir tu propia versión de Dense, ver cuándo se crean sus pesos, comprobar que da lo mismo que la oficial y que sus gradientes coinciden con los calculados a mano, y recrearla desde su configuración.

import re
import numpy as np
import tensorflow as tf
import keras
from keras import layers

class CapaDensa(layers.Layer):
    def __init__(self, unidades, activacion=None, **kwargs):
        super().__init__(**kwargs)
        self.unidades = unidades
        self.activacion = keras.activations.get(activacion)

    def build(self, input_shape):
        n_in = input_shape[-1]
        self.W = self.add_weight(name="W", shape=(n_in, self.unidades), initializer="glorot_uniform")
        self.b = self.add_weight(name="b", shape=(self.unidades,), initializer="zeros")

    def call(self, x):
        return self.activacion(tf.matmul(x, self.W) + self.b)

    def get_config(self):
        config = super().get_config()
        config.update({"unidades": self.unidades, "activacion": keras.activations.serialize(self.activacion)})
        return config

18 · Guardar y cargar con una capa propia: registro, custom_objects, pesos y Lambda

Para qué sirve Ver qué ocurre al guardar un modelo con una capa propia: el error al cargarla sin registrar, las dos soluciones, el formato de solo pesos, los errores de formatos antiguos y el rechazo de Lambda.

import os
import re
import tempfile
import numpy as np
import keras
from keras import layers

class CapaEscala(layers.Layer):
    def __init__(self, factor=2.0, **kwargs):
        super().__init__(**kwargs)
        self.factor = factor

    def call(self, x):
        return x * self.factor

    def get_config(self):
        config = super().get_config()
        config["factor"] = self.factor
        return config

def construir(clase):
    entrada = keras.Input(shape=(3,), name="x")
    return keras.Model(entrada, layers.Dense(2, name="salida")(clase(factor=3.0, name="escala")(entrada)))

ruta = os.path.join(carpeta, "modelo.keras")
x = np.array([[1.0, 2.0, 3.0]], dtype="float32")

modelo = construir(CapaEscala)
modelo.save(ruta)
try:
    keras.models.load_model(ruta)
except TypeError as e:
    print("sin registrar:", re.search(r"Could not locate class '\w+'", str(e)).group(0))

cargado = keras.models.load_model(ruta, custom_objects={"CapaEscala": CapaEscala})
print("con custom_objects:", np.allclose(modelo(x), cargado(x)))

19 · Guardar un modelo por subclases (get_config) y exportar un SavedModel

Para qué sirve Mostrar que un modelo por subclases con argumentos en __init__ necesita get_config para guardarse bien, y exportar un modelo al formato SavedModel de TensorFlow.

import contextlib
import io
import os
import re
import tempfile
import numpy as np
import tensorflow as tf
import keras
from keras import layers

def definir(con_config):
    class Mini(keras.Model):
        def __init__(self, ocultas=4, **kwargs):
            super().__init__(**kwargs)
            self.ocultas = ocultas
            self.d1 = layers.Dense(ocultas, activation="relu")
            self.d2 = layers.Dense(1)

        def call(self, x):
            return self.d2(self.d1(x))

    if con_config:
        def get_config(self):
            config = super(Mini, self).get_config()
            config["ocultas"] = self.ocultas
            return config
        Mini.get_config = get_config
    return Mini

carpeta = tempfile.mkdtemp()
x = np.array([[1.0, 2.0, 3.0], [0.5, -1.0, 0.0]], dtype="float32")
keras.utils.set_random_seed(0)

for con_config in (False, True):
    Mini = definir(con_config)
    modelo = Mini(ocultas=5, name="mini")
    modelo(x)
    ruta = os.path.join(carpeta, f"mini_{con_config}.keras")
    modelo.save(ruta)
    try:
        cargado = keras.models.load_model(ruta, custom_objects={"Mini": Mini})
