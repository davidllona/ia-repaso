Cuando la accuracy empata, el framework lo eligen los pesos del proyecto

Keras y PyTorch empatan en notas. La elección se justifica con una tabla de decisión: criterios que importan a este proyecto, una nota con cifra medida para cada uno y un peso según el contexto.

Índice del módulo

Keras y PyTorch han empatado en accuracy. Tu equipo va a meter el clasificador de pósters dentro de una app móvil. ¿Sigue siendo un empate?

No. Cuando el rendimiento empata, deciden los demás criterios, y en móvil pesa el despliegue: TensorFlow tiene LiteRT (antes TFLite) y TF.js muy rodados. En un laboratorio de investigación, el mismo empate se rompería hacia PyTorch. No hay un ganador universal.

Cinco pasos para decidir (y poder defenderlo)

  1. Lista los criterios que le importan a tu proyecto: rendimiento, rapidez para prototipar, control, despliegue, lo que sabe el equipo.
  2. Pon una nota de 1 a 5 a cada framework, apoyada en una cifra medida: 0,932 frente a 0,948 de accuracy, 9 frente a 21 líneas, milisegundos por póster.
  3. Pon un peso de 0 a 5 a cada criterio según el contexto: un curso, una app móvil, un laboratorio.
  4. Calcula la media ponderada: suma de peso × nota, dividida entre la suma de pesos.
  5. Escribe la justificación en una frase con cifras y con sus límites.

Con números: el proyecto de curso

Ejemplo numérico

Pesos: rendimiento 3, prototipar 4, control 2, móvil 1, equipo 3 (no domina ninguno: nota 3 y 3). La suma de pesos es 13.

  1. Keras: 3·4 + 4·5 + 2·3 + 1·5 + 3·3 = 12 + 20 + 6 + 5 + 9 = 52 → 52 / 13 = 4,00.
  2. PyTorch: 3·4 + 4·3 + 2·5 + 1·3 + 3·3 = 12 + 12 + 10 + 3 + 9 = 46 → 46 / 13 = 3,54.
  3. Gana Keras por 0,46, y no por el rendimiento (los dos tienen 4 ahí): por prototipar y desplegar.
Plantilla de justificación

«Elegimos Keras porque en este proyecto pesa prototipar: entrenar, validar y guardar el mejor modelo son 9 líneas frente a 21. En rendimiento empatan (0,932 ± 0,031 frente a 0,948 ± 0,010 en 3 semillas). Limitaciones: CPU de un hilo, 3 semillas y pósters sintéticos.»

Mismos pesos de «proyecto de curso», pero el equipo resulta dominar PyTorch (nota 5 para PyTorch y 2 para Keras en ese criterio). ¿Cambia la elección?

Sí. Keras baja a (12 + 20 + 6 + 5 + 6) / 13 = 49 / 13 = 3,77 y PyTorch sube a (12 + 12 + 10 + 3 + 15) / 13 = 52 / 13 = 4,00. Lo que el equipo ya sabe pesa tanto como la ventaja de prototipar.

Profundizar: la explicación completaQué se guarda y cuánto ocupa, rutas de despliegue de cada framework, por qué la latencia cambia tanto según cómo llames al modelo y qué llevar a la presentación final.

Despliegue: lo que el notebook no te enseña

Qué se guarda y cuánto ocupa

mejor.keras ocupa 1.093 KB porque lleva arquitectura, pesos y el estado de Adam (dos números más por peso: 89.249 × 4 bytes × 3 ≈ 1.046 KB). mejor.pt solo lleva los pesos: 352 KB, pero para usarlo necesitas el código de RedPosters. red.pt2, de torch.export, lleva pesos y el cálculo ya trazado, sin depender de tu archivo de Python: 394 KB. Para servir, nadie necesita el estado del optimizador.

Rutas de despliegue de cada framework

  • Keras / TensorFlow: model.export("carpeta") genera un SavedModel para TF Serving; el conversor de LiteRT lo lleva a móvil (con cuantización a 8 bits, unas 4 veces más pequeño); TF.js lo ejecuta en el navegador.
  • PyTorch: torch.export produce un programa sin Python (.pt2); ExecuTorch lo lleva a móvil; torch.onnx.export lo pasa a ONNX, que ONNX Runtime ejecuta en casi cualquier sitio, incluido el navegador.

ONNX es el puente: puedes entrenar en PyTorch y servir donde haga falta. Por eso el criterio «despliegue» pesa menos que hace unos años, aunque la ruta de TensorFlow a móvil sigue siendo la más directa.

La latencia que mediste

Con un solo póster, Keras predict() tardó 62,64 ms; llamar al modelo directamente, 8,21 ms; envolverlo en tf.function, 1,11 ms; PyTorch en modo eval, 0,27 ms. La diferencia de 60 ms no es la red (son las mismas cuentas): es la sobrecarga de cada forma de llamarla. Con lotes de cientos de pósters estas cifras se igualan. Mide siempre tu caso de uso: una imagen cada vez o lotes.

Ojo · justificaciones que no se sostienen

«Es más moderno», «es el que usa Google», «sacó medio punto más en una ejecución». Ninguna dice qué criterio importa en tu proyecto ni lo apoya en una cifra. Y si el equipo domina un framework, dilo: es un motivo legítimo, no una debilidad.

Código

1 · Despliegue con números: tamaño en disco y milisegundos por póster

Para qué sirve Medir lo que importa al servir el modelo: cuánto ocupa el archivo y cuánto tarda en clasificar un póster. Se lanza dos veces: python desplegar.py keras y python desplegar.py torch. Necesita mejor.keras (lección 2), mejor.pt (lección 3), posters.py y cnn_torch.py.

import os, sys, time
import numpy as np
from posters import crear_posters

X, _ = crear_posters(1, semilla=3)               # un póster nuevo: (1, 32, 32, 3)

def cronometrar(f, veces=200):
    f()                                          # una llamada de calentamiento
    t = time.perf_counter()
    for _ in range(veces):
        f()
    return (time.perf_counter() - t) / veces * 1000

if sys.argv[1] == "keras":
    import keras
    m = keras.models.load_model("mejor.keras")
    print("mejor.keras: %.0f KB" % (os.path.getsize("mejor.keras") / 1024))
    print("predict(): %.2f ms" % cronometrar(lambda: m.predict(X, verbose=0), 50))
    print("m(x):      %.2f ms" % cronometrar(lambda: m(X, training=False)))
    import tensorflow as tf
    rapido = tf.function(lambda x: m(x, training=False))   # grafo compilado
    print("grafo:     %.2f ms" % cronometrar(lambda: rapido(X)))
else:
    import torch
    from cnn_torch import RedPosters
    red = RedPosters()
    red.load_state_dict(torch.load("mejor.pt"))
    red.eval()
    x = torch.from_numpy(X).permute(0, 3, 1, 2)
    print("mejor.pt (solo pesos): %.0f KB" % (os.path.getsize("mejor.pt") / 1024))
    prog = torch.export.export(red, (x,))        # modelo + código, sin Python
    torch.export.save(prog, "red.pt2")
    print("red.pt2 (exportado):   %.0f KB" % (os.path.getsize("red.pt2") / 1024))
    with torch.no_grad():
        print("red(x): %.2f ms" % cronometrar(lambda: red(x)))
