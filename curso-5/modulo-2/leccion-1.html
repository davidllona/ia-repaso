Redes profundas: más capas, un solo bloque de código

Una red profunda (deep network) es una red con varias capas ocultas apiladas. Cada capa toma la salida de la anterior, la mezcla con sus pesos y le aplica una activación. La primera capa detecta cosas sencillas de la entrada; las siguientes combinan esas cosas en otras más complejas. Con la carátula de una película: bordes → formas → ojos → «es la cara de Woody». Recuerda (Curso 2 · módulo 1 y módulo anterior)

Una capa densa calcula \( h=f(Wx+b) \): multiplica por los pesos \( W \), suma el sesgo \( b \) y aplica la activación \( f \). En el módulo anterior construiste esa capa con nn.Linear y la activación ReLU o sigmoide, y viste cómo una capa oculta resuelve el XOR. Una red profunda es lo mismo repetido: \( h_1=f(W_1x+b_1) \), \( h_2=f(W_2h_1+b_2) \), … y una última capa lineal que da la salida.

Analogía

Hacer una película es una cadena de pasos: guion → rodaje → montaje → efectos → mezcla de sonido. Con un único equipo gigante tendría que hacerlo todo a la vez; con varios, cada uno hace una tarea sencilla sobre el resultado del anterior. Pero ojo: si el rodaje sale mal, el montaje, los efectos y el sonido trabajan con material estropeado. De eso va casi todo el módulo.

Cuántos parámetros tiene: la cuenta a mano

Una capa nn.Linear(entradas, salidas) tiene una matriz de pesos de forma (salidas, entradas) (una fila por neurona) y un vector de sesgos con salidas elementos. Por tanto:

\[ \text{parámetros de una capa} = \underbrace{n_{\text{ent}}\cdot n_{\text{sal}}}_{\text{pesos}} + \underbrace{n_{\text{sal}}}_{\text{sesgos}} \]

Cómo se escribe: nn.ModuleList

Para no escribir cada capa a mano, se guardan en un nn.ModuleList. Es como una lista de Python, pero con un superpoder: avisa a la red de que esas capas son suyas. El fragmento 1 construye RedProfunda([64, 32, 32, 32, 10]) con un bucle y su método forward recorre la lista; también muestra la alternativa corta con nn.Sequential.

Regla fácil

Si guardas capas dentro de un nn.Module, que sea en nn.ModuleList (o nn.Sequential, o nn.ModuleDict), nunca en una lista o diccionario normal de Python.

Ojo

Con una lista de Python no hay error al construir ni al hacer el forward: la red parece funcionar. El fallo aparece al crear el optimizador (ValueError: optimizer got an empty parameter list) o, peor, si el modelo tiene además alguna capa registrada, la red entrena solo esas capas y las demás se quedan con sus pesos aleatorios. El fragmento 1 lo provoca a propósito.

Recuerda (Keras)

En Keras escribías Sequential([Dense(32, activation="relu"), …]) y el número de entradas de cada capa se deducía solo. En PyTorch nn.Linear(64, 32) pide las dos cifras, y la activación es un paso aparte (torch.relu(...) o nn.ReLU()). Los pesos por defecto también cambian, como verás en la sección de inicialización.

11 · BatchNorm en una red de 10 capas sigmoides

Para qué sirve Medir el efecto de BatchNorm sobre los gradientes por capa y sobre el entrenamiento en una red con sigmoides, el peor caso para el gradiente que se desvanece.

import torch
import torch.nn as nn
from sklearn.datasets import load_digits

X, y = load_digits(return_X_y=True)
X = torch.tensor(X / 16.0, dtype=torch.float32)
y = torch.tensor(y)
perdida = nn.CrossEntropyLoss()


def construir(con_bn, capas_ocultas=10, ancho=32):
    torch.manual_seed(0)
    modulos, entrada = [], 64
    for _ in range(capas_ocultas):
        modulos.append(nn.Linear(entrada, ancho))
        if con_bn:
            modulos.append(nn.BatchNorm1d(ancho))
        modulos.append(nn.Sigmoid())
        entrada = ancho
    modulos.append(nn.Linear(entrada, 10))
    return nn.Sequential(*modulos)


for con_bn in [False, True]:
    modelo = construir(con_bn)
    perdida(modelo(X[:256]), y[:256]).backward()
    normas = [m.weight.grad.norm().item() for m in modelo if isinstance(m, nn.Linear)]
    print(f"{'con' if con_bn else 'sin'} BatchNorm: capa 1 = {normas[0]:.1e}, capa 11 = {normas[-1]:.1e}, cociente = {normas[0] / normas[-1]:.1e}")

    modelo = construir(con_bn)
    optimizador = torch.optim.SGD(modelo.parameters(), lr=0.1)
    g = torch.Generator().manual_seed(0)
    historial = []
    for paso in range(1, 301):
        idx = torch.randint(0, 1500, (64,), generator=g)
        optimizador.zero_grad()
        l = perdida(modelo(X[idx]), y[idx])
        l.backward()
        optimizador.step()
        if paso in (1, 50, 100, 200, 300):
            historial.append(round(l.item(), 3))
    print("   pérdida en los pasos 1, 50, 100, 200, 300:", historial)

13 · Carrera de optimizadores en una red de 6 capas

Para qué sirve Entrenar la misma red profunda de 6 capas (ReLU + He) con seis optimizadores sobre los dígitos y medir cuánto bajan la pérdida y el acierto en test, promediando 3 semillas.

import numpy as np
import torch
import torch.nn as nn
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split
from torch.utils.data import DataLoader, TensorDataset

torch.set_num_threads(1)
X, y = load_digits(return_X_y=True)
Xtr, Xte, ytr, yte = train_test_split(X / 16.0, y, test_size=0.25, random_state=0, stratify=y)
Xtr, Xte = torch.tensor(Xtr, dtype=torch.float32), torch.tensor(Xte, dtype=torch.float32)
ytr, yte = torch.tensor(ytr), torch.tensor(yte)
perdida = nn.CrossEntropyLoss()


def construir(semilla):
    torch.manual_seed(semilla)
    modulos, entrada = [], 64
    for _ in range(6):
        lineal = nn.Linear(entrada, 64)
        nn.init.kaiming_normal_(lineal.weight, nonlinearity="relu")
        nn.init.zeros_(lineal.bias)
        modulos += [lineal, nn.ReLU()]
        entrada = 64
    modulos.append(nn.Linear(64, 10))
    return nn.Sequential(*modulos)


def entrenar(crear_opt, semilla, epocas=30):
    modelo = construir(semilla)
    opt = crear_opt(modelo.parameters())
    datos = DataLoader(TensorDataset(Xtr, ytr), batch_size=64, shuffle=True, drop_last=True,
                       generator=torch.Generator().manual_seed(semilla))
    curva = []
    for _ in range(epocas):
        modelo.train()
        for xb, yb in datos:
            opt.zero_grad()
            perdida(modelo(xb), yb).backward()
            opt.step()
        modelo.eval()
        with torch.no_grad():
            curva.append(perdida(modelo(Xtr), ytr).item())
    with torch.no_grad():
        acc = (modelo(Xte).argmax(1) == yte).float().mean().item()
    return curva, acc


opts = {
    "SGD lr=0.01": lambda p: torch.optim.SGD(p, lr=0.01),
    "SGD + momentum 0.9": lambda p: torch.optim.SGD(p, lr=0.01, momentum=0.9),
    "SGD + Nesterov": lambda p: torch.optim.SGD(p, lr=0.01, momentum=0.9, nesterov=True),
    "RMSprop lr=1e-3": lambda p: torch.optim.RMSprop(p, lr=1e-3),
    "Adam lr=1e-3": lambda p: torch.optim.Adam(p, lr=1e-3),
    "Adam lr=1e-2": lambda p: torch.optim.Adam(p, lr=1e-2),
}
print(f"{'optimizador':20s} {'ép.1':>7s} {'ép.5':>7s} {'ép.10':>7s} {'ép.30':>7s} {'acierto test':>13s}")
for nombre, crear in opts.items():
    r = [entrenar(crear, s) for s in range(3)]
    curva = np.mean([c for c, _ in r], axis=0)
    acc = np.mean([a for _, a in r])
    print(f"{nombre:20s} {curva[0]:7.3f} {curva[4]:7.3f} {curva[9]:7.3f} {curva[29]:7.3f} {acc:13.3f}")

Con \(lr=0.01\), SGD simple va lentísimo: tras 30 épocas la pérdida sigue en 0.247 y acierta 90.5 %. El momentum 0.9 equivale a un lr efectivo hasta 10 veces mayor: pérdida 0.004 y 96.5 %. Nesterov (96.6 %), RMSprop (96.7 %) y Adam (96.9 %) llegan igual de lejos. Adam con lr \(10^{-2}\) baja muy rápido al principio (0.424 en la época 1) pero acaba peor en entrenamiento (0.048) por su ruido. Moraleja: casi todo se arregla con un lr adecuado; lo que aporta Adam es que acierta con menos ajuste.
