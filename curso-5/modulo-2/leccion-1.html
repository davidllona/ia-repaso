Una red profunda es la misma capa repetida, guardada en nn.ModuleList

Una red profunda apila capas: cada una trabaja sobre lo que le entrega la anterior, como los equipos de un rodaje. En PyTorch se escribe con un bucle, y las capas se guardan en nn.ModuleList para que la red sepa que son suyas.

Índice del módulo

Tu red de carátulas es [64, 32, 32, 32, 10] y tiene 4.522 parámetros. Si le añades otra capa oculta de 32 neuronas, ¿cuántos parámetros ganas: unos 100, unos 1.000 o unos 10.000?

Unos 1.000: exactamente 1.056. Una capa 32 → 32 tiene 32·32 = 1.024 pesos (una fila de 32 por neurona) y 32 sesgos. Cada capa igual suma lo mismo: el total crece en línea recta con la profundidad, pero con el cuadrado de la anchura.

Capas en fila, como un rodaje

Hacer una película es una cadena: guion → rodaje → montaje → efectos → sonido. Cada equipo hace algo sencillo sobre lo que le entrega el anterior. Una red profunda es igual: varias capas ocultas en fila, y cada una calcula \( h=f(Wx+b) \) con la salida de la anterior. La primera ve cosas simples de la carátula (bordes); las siguientes las combinan (formas, ojos… «es la cara de Woody»).

Cada nn.Linear(entradas, salidas) guarda una matriz de pesos de forma (salidas, entradas), una fila por neurona, y un sesgo por neurona. Por eso tiene \( n_{\text{ent}}\cdot n_{\text{sal}}+n_{\text{sal}} \) parámetros.

Para no escribir veinte capas a mano se crean con un bucle y se guardan en nn.ModuleList: una lista que además registra las capas en la red, para que aparezcan en model.parameters(), viajen a la GPU y se guarden. Con una lista normal de Python la red hace el forward sin quejarse, pero el optimizador no ve ningún peso.

Guardas las capas en self.capas = [nn.Linear(64, 32), …], una lista de Python. ¿Cuándo salta el error: al construir la red, al hacer el forward o al crear el optimizador?

Al crear el optimizador: ValueError: optimizer got an empty parameter list. Construir y hacer el forward funcionan porque las capas existen; lo que falla es que la red no sabe que son suyas. Y si hay alguna otra capa registrada, ni siquiera hay error: la red entrena solo esa.

En tres líneas

  • Red profunda = capas \( h=f(Wx+b) \) en fila; cada una trabaja sobre la salida de la anterior.
  • nn.Linear(n_ent, n_sal) tiene n_ent·n_sal + n_sal parámetros: [64, 32, 32, 32, 10] suma 4.522.
  • Capas en nn.ModuleList o nn.Sequential, nunca en una lista de Python.

Redes profundas: más capas, un solo bloque de código

Netflix no decide qué recomendarte de un solo vistazo: primero mira cosas sencillas y luego las combina. ¿Qué significa «profunda» y cómo escribo una red de 3, de 8 o de 20 capas sin copiar y pegar el mismo código?

Una red profunda (deep network) es una red con varias capas ocultas apiladas. Cada capa toma la salida de la anterior, la mezcla con sus pesos y le aplica una activación. La primera capa detecta cosas sencillas de la entrada; las siguientes combinan esas cosas en otras más complejas. Con la carátula de una película: bordes → formas → ojos → «es la cara de Woody». Con tus gustos: «ve comedias» + «ve cosas cortas» → «le va bien una comedia corta para cenar».

Recuerda (Curso 2 · módulo 1 y módulo anterior)

Una capa densa calcula \( h=f(Wx+b) \): multiplica por los pesos \( W \), suma el sesgo \( b \) y aplica la activación \( f \). En el módulo anterior construiste esa capa con nn.Linear y la activación ReLU o sigmoide, y viste cómo una capa oculta resuelve el XOR. Una red profunda es lo mismo repetido: \( h_1=f(W_1x+b_1) \), \( h_2=f(W_2h_1+b_2) \), … y una última capa lineal que da la salida.

Analogía

Hacer una película es una cadena de pasos: guion → rodaje → montaje → efectos → mezcla de sonido. Con un único equipo gigante tendría que hacerlo todo a la vez; con varios, cada uno hace una tarea sencilla sobre el resultado del anterior. Pero ojo: si el rodaje sale mal, el montaje, los efectos y el sonido trabajan con material estropeado. De eso va casi todo el módulo.

Cuántos parámetros tiene: la cuenta a mano

Una capa nn.Linear(entradas, salidas) tiene una matriz de pesos de forma (salidas, entradas) (una fila por neurona) y un vector de sesgos con salidas elementos. Por tanto:

\[ \text{parámetros de una capa} = \underbrace{n_{\text{ent}}\cdot n_{\text{sal}}}_{\text{pesos}} + \underbrace{n_{\text{sal}}}_{\text{sesgos}} \]

Cómo se escribe: nn.ModuleList

Para no escribir cada capa a mano, se guardan en un nn.ModuleList. Es como una lista de Python, pero con un superpoder: avisa a la red de que esas capas son suyas. El fragmento 1 construye RedProfunda([64, 32, 32, 32, 10]) con un bucle y su método forward recorre la lista; también muestra la alternativa corta con nn.Sequential.

Regla fácil

Si guardas capas dentro de un nn.Module, que sea en nn.ModuleList (o nn.Sequential, o nn.ModuleDict), nunca en una lista o diccionario normal de Python.

Ojo

Con una lista de Python no hay error al construir ni al hacer el forward: la red parece funcionar. El fallo aparece al crear el optimizador (ValueError: optimizer got an empty parameter list) o, peor, si el modelo tiene además alguna capa registrada, la red entrena solo esas capas y las demás se quedan con sus pesos aleatorios. El fragmento 1 lo provoca a propósito.

Recuerda (Keras)

En Keras escribías Sequential([Dense(32, activation="relu"), …]) y el número de entradas de cada capa se deducía solo. En PyTorch nn.Linear(64, 32) pide las dos cifras, y la activación es un paso aparte (torch.relu(...) o nn.ReLU()). Los pesos por defecto también cambian, como verás en la sección de inicialización.

1 · Red profunda con nn.ModuleList (y por qué no vale una lista normal)

Para qué sirve Construir una red de cualquier número de capas a partir de una lista de tamaños, contar sus parámetros y ver qué pasa si guardas las capas en una lista de Python en lugar de en nn.ModuleList.

import torch
import torch.nn as nn


class RedProfunda(nn.Module):
    def __init__(self, tamanos):
        super().__init__()
        self.capas = nn.ModuleList(
            [nn.Linear(tamanos[i], tamanos[i + 1]) for i in range(len(tamanos) - 1)]
        )

    def forward(self, x):
        for capa in self.capas[:-1]:
            x = torch.relu(capa(x))
        return self.capas[-1](x)


torch.manual_seed(0)
modelo = RedProfunda([64, 32, 32, 32, 10])
print(modelo)

total = 0
for nombre, p in modelo.named_parameters():
    print(f"{nombre:16s} {str(tuple(p.shape)):10s} {p.numel():5d}")
    total += p.numel()
print("parámetros totales:", total)
print("salida para un lote de 5:", tuple(modelo(torch.randn(5, 64)).shape))


def construir_mlp(tamanos):
    capas = []
    for i in range(len(tamanos) - 1):
        capas.append(nn.Linear(tamanos[i], tamanos[i + 1]))
        if i < len(tamanos) - 2:
            capas.append(nn.ReLU())
    return nn.Sequential(*capas)


otro = construir_mlp([64, 32, 32, 32, 10])
print("con Sequential:", sum(p.numel() for p in otro.parameters()), "parámetros")


class RedMala(nn.Module):
    def __init__(self):
        super().__init__()
        self.capas = [nn.Linear(4, 4), nn.Linear(4, 1)]   # lista normal de Python

    def forward(self, x):
        return self.capas[1](torch.relu(self.capas[0](x)))


mala = RedMala()
print("parámetros que ve RedMala:", len(list(mala.parameters())))
try:
    torch.optim.SGD(mala.parameters(), lr=0.1)
except ValueError as e:
    print("ValueError:", e)
