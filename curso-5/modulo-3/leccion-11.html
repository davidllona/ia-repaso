¿Reconoce el dígito si se mueve? Equivarianza, invariancia y data augmentation

Hay que separar dos propiedades. La convolución es equivariante: si desplazas la entrada, el mapa de características se desplaza igual, el mismo patrón en otro sitio. Eso no es lo mismo que invariante (que la salida final no cambie). Lo que hace que el final sea más o menos invariante son las etapas posteriores: el pooling absorbe desplazamientos pequeños si no cruzan el borde de la ventana, y el pooling global (AdaptiveAvgPool2d(1) o un máximo global) absorbe todos. Pero el Flatten seguido de Linear da a cada posición su propio peso, y rompe buena parte de la invariancia.

¿Reconoce el dígito si se mueve? Equivarianza, invariancia y data augmentation

Se dice que las CNN «son invariantes a traslaciones»: Woody se reconoce lo mismo en el centro del póster que en una esquina. ¿Es verdad? ¿Qué ocurre si desplazo la miniatura de prueba un solo píxel?

Ejemplo numérico: el pooling absorbe unos desplazamientos y otros no (fragmento 5)

Un fotograma nocturno de 6×6 (el cielo es todo ceros) con una estrella brillante, un 9, en la posición (2, 2). MaxPool2d(2) mira ventanas 2×2: la que cubre filas 2–3 y columnas 2–3 contiene el 9 y da 9. Si la estrella se mueve un píxel hacia abajo y a la derecha, pasa a (3, 3): sigue en la misma ventana y la salida es idéntica. Si se mueve un píxel hacia arriba, pasa a (1, 2): cae en la ventana de las filas 0–1, y la salida es distinta. El fragmento 5 lo comprueba con torch.roll (igual: True y False).

Qué dice y qué no dice la tabla: (1) Con las imágenes sin mover, las dos redes son iguales (0,976 y 0,978). Una prueba normal no distingue una de otra. (2) Un solo píxel hunde ambas: la densa cae a 0,41–0,48 (y a 0,156 en diagonal) y la CNN es mejor pero lejos de ser invariante (0,34–0,63). En una imagen de 8 píxeles, un píxel es el 12,5 % del lado: es un desplazamiento enorme. (3) La solución es mostrar desplazamientos al entrenar: con augmentation la CNN pasa a 0,91–0,97 en todos los casos, y la densa, que sigue peor, a 0,81–0,88. (4) El augmentation tiene un coste en las imágenes sin mover (la densa pierde 0,085, la CNN 0,028), porque en 8×8 los desplazamientos recortan parte del dígito. Hay más detalles que se simplifican: el desplazamiento es el mismo para todo el lote, no distinto en cada imagen, y solo se han probado tres semillas.

Ojo

«Las CNN son invariantes a traslaciones» es una simplificación peligrosa: lo son mucho más que una red densa, pero no del todo, y menos con pocos pooling y un Flatten grande. Si tu problema necesita tolerar desplazamientos, giros o cambios de escala, métele variaciones en el entrenamiento (data augmentation, que verás con torchvision.transforms en el módulo siguiente) y mide con imágenes transformadas.

13 · ¿Y si el dígito se mueve? Red densa y CNN, con y sin data augmentation

Para qué sirve Entrenar una red densa y una CNN con dígitos de 8×8, probarlas con imágenes desplazadas un píxel y repetirlo entrenando con desplazamientos aleatorios (data augmentation). Tres semillas por casilla.

import torch
import torch.nn as nn
import torch.nn.functional as F
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split
from torch.utils.data import TensorDataset, DataLoader

torch.set_num_threads(1)

digitos = load_digits()
X = torch.tensor(digitos.images, dtype=torch.float32).unsqueeze(1) / 16.0
y = torch.tensor(digitos.target, dtype=torch.long)
idx_tr, idx_te = train_test_split(range(len(y)), test_size=0.25, stratify=y.numpy(), random_state=0)
X_tr, y_tr, X_te, y_te = X[idx_tr], y[idx_tr], X[idx_te], y[idx_te]


def densa():
    return nn.Sequential(nn.Flatten(), nn.Linear(64, 32), nn.ReLU(), nn.Linear(32, 10))


def conv():
    return nn.Sequential(
        nn.Conv2d(1, 8, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
        nn.Conv2d(8, 16, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
        nn.Flatten(), nn.Linear(64, 10),
    )


def desplazar(x, dx=0, dy=0):
    x = F.pad(x, (max(dx, 0), max(-dx, 0), max(dy, 0), max(-dy, 0)))
    h, w = x.shape[-2:]
    return x[..., max(-dy, 0):h - max(dy, 0), max(-dx, 0):w - max(dx, 0)]


def acierto(modelo, X, y):
    modelo.eval()
    with torch.no_grad():
        return (modelo(X).argmax(1) == y).float().mean().item()


def entrenar(fabrica, semilla, aumentar=False):
    torch.manual_seed(semilla)
    modelo = fabrica()
    cargador = DataLoader(TensorDataset(X_tr, y_tr), batch_size=64, shuffle=True)
    optimizador = torch.optim.Adam(modelo.parameters(), lr=0.01)
    criterio = nn.CrossEntropyLoss()
    for _ in range(25):
        modelo.train()
        for lx, ly in cargador:
            if aumentar:
                dx, dy = torch.randint(-1, 2, (2,)).tolist()
                lx = desplazar(lx, dx, dy)
            optimizador.zero_grad()
            criterio(modelo(lx), ly).backward()
            optimizador.step()
    return modelo


print("parámetros  densa:", sum(p.numel() for p in densa().parameters()), "| CNN:", sum(p.numel() for p in conv().parameters()))
pruebas = [("sin mover", 0, 0), ("1 px a la derecha", 1, 0), ("1 px abajo", 0, 1), ("1 px izquierda y arriba", -1, -1)]
modelos = [("densa", densa, False), ("CNN", conv, False), ("densa + aug", densa, True), ("CNN + aug", conv, True)]
res = {n: {p[0]: [] for p in pruebas} for n, _, _ in modelos}
for semilla in (0, 1, 2):
    for nombre, fabrica, aug in modelos:
        m = entrenar(fabrica, semilla, aug)
        for etiqueta, dx, dy in pruebas:
            res[nombre][etiqueta].append(acierto(m, desplazar(X_te, dx, dy), y_te))
print(f"{'imagen de prueba':<26}" + "".join(f"{n:>13}" for n, _, _ in modelos))
for etiqueta, _, _ in pruebas:
    print(f"{etiqueta:<26}" + "".join(f"{sum(res[n][etiqueta]) / 3:13.3f}" for n, _, _ in modelos))
