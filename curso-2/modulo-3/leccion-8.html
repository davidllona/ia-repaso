ReLU después de la convolución

Una convolución es una operación lineal (multiplicar y sumar). Y encadenar dos operaciones lineales da otra operación lineal. Con números: convolucionar una fila con el filtro \( [1, 1] \) y luego con otro \( [1, 1] \) equivale a hacerlo una sola vez con el filtro \( [1, 2, 1] \) (los dos filtros combinados: \( [1,1] * [1,1] = [1,2,1] \)). Dos capas lineales serían tan expresivas como una. Poner ReLU entre ellas rompe la linealidad y permite que cada capa aporte algo nuevo (es el mismo argumento que viste para las capas densas en el módulo 1).

La salida del filtro dice «cuánto se parece este parche al patrón del filtro». Un valor grande y positivo significa «sí, aquí está»; uno negativo, «aquí aparece el patrón contrario»; 0, «nada». ReLU conserva la evidencia a favor y borra el resto, y deja mapas dispersos (muchos ceros), que son baratos y más fáciles de interpretar.

Por eso una capa convolucional completa hace tres cosas, en este orden: convolución → sumar el bias → ReLU. En Keras: Conv2D(16, (5,5), activation="relu").

ReLU después de la convolución

En una Conv2D de Keras casi siempre aparece activation="relu". ¿Por qué?

Recuerda (módulo 1)

ReLU es la función \( \text{ReLU}(x) = \max(0, x) \): deja pasar los positivos y pone a 0 los negativos. Se aplica a cada valor del mapa por separado.

Razón 1: sin una no linealidad, apilar convoluciones no sirve de nada

Razón 2: es una forma natural de leer la respuesta del filtro

Ejemplo numérico

Una fila del mapa del fotograma de la sala y la pantalla (ejemplo de la convolución): [0, 21, 22] con el filtro «oscuro → claro». Con el filtro invertido («claro → oscuro») la misma fila sale con los signos cambiados: [0, −21, −22].

  1. ReLU de [0, 21, 22] = [max(0,0), max(0,21), max(0,22)] = [0, 21, 22] → el borde de la pantalla está ahí.
  2. ReLU de [0, −21, −22] = [0, 0, 0] → este filtro no ve nada (el borde está al revés).

Por eso una capa convolucional completa hace tres cosas, en este orden: convolución → sumar el bias → ReLU. En Keras: Conv2D(16, (5,5), activation="relu").

¿Por qué ReLU y no sigmoide o tanh? Por lo que viste con el vanishing gradient: las sigmoides se saturan y el gradiente se apaga en redes profundas; ReLU tiene pendiente 1 para los positivos, es barata de calcular y entrena mucho más rápido. Es la opción por defecto en capas ocultas de CNN.

2 · Convolución frente a correlación: ¿gira el filtro Keras?

Para qué sirve Comprobar con SciPy y con keras.ops.conv lo que dijimos en el recuadro «Ojo»: las librerías de Deep Learning no giran el filtro. También enseña la forma de los tensores que pide Keras ((lote, alto, ancho, canales) y (alto, ancho, canales_entrada, filtros)).

import numpy as np
from scipy.signal import correlate2d, convolve2d
import keras

imagen = np.array([
    [1, 1, 2, 8, 9],
    [1, 2, 1, 9, 8],
    [2, 1, 1, 8, 9],
    [1, 1, 2, 9, 9],
    [1, 2, 1, 8, 8],
])
filtro = np.array([
    [-1, 0, 1],
    [-1, 0, 1],
    [-1, 0, 1],
])

corr = correlate2d(imagen, filtro, mode="valid")
print("correlate2d:")
print(corr)

conv = convolve2d(imagen, filtro, mode="valid")
print("convolve2d (gira el filtro 180 grados):")
print(conv)

girado = np.rot90(filtro, 2)
print("convolve2d con filtro ya girado == correlate2d:",
      np.array_equal(convolve2d(imagen, girado, mode="valid"), corr))

x = imagen.reshape(1, 5, 5, 1).astype("float32")
k = filtro.reshape(3, 3, 1, 1).astype("float32")
salida_keras = keras.ops.conv(x, k, strides=1, padding="valid")
print("keras.ops.conv, forma:", salida_keras.shape)
print(np.array(salida_keras)[0, :, :, 0])
print("Keras coincide con correlate2d:",
      np.allclose(np.array(salida_keras)[0, :, :, 0], corr))
