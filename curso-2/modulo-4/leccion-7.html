GPT: un Transformer que predice la siguiente palabra

Si le escribes «El detective persigue al…» a un chatbot y te contesta con un párrafo coherente (con su ladrón y su persecución), ¿qué ha hecho por dentro? ¿Cómo se pasa de «una capa de atención» a «una IA que escribe»?

El nombre ya lo explica todo

GPT significa Generative Pre-trained Transformer:

  • Generative (generativo): su trabajo es producir texto, no solo clasificarlo.
  • Pre-trained (preentrenado): primero aprende, con una cantidad gigantesca de texto, a completar frases; después se adapta a tareas concretas.
  • Transformer: la arquitectura de la sección anterior. En concreto, un Transformer de solo decoder: una pila de bloques con atención con máscara causal, de modo que cada token solo ve los anteriores.

El bucle: una palabra, otra palabra, otra palabra…

Un GPT hace una sola cosa, una y otra vez: dado el texto que hay hasta ahora, calcular la probabilidad de cada posible siguiente token. Para escribir un párrafo repite el ciclo:

  • Contexto«El detective persigue al»
  • Transformerbloques con atención causal
  • Probabilidadesde cada token del vocabulario
  • Se elige uno«ladrón»
  • Nuevo contexto«El detective persigue al ladrón»

…y se vuelve al principio con el contexto ampliado, hasta que el modelo elige un token especial de «fin» o se alcanza el límite. Se llama generación autorregresiva: cada token que el modelo produce pasa a ser parte de la entrada del siguiente.

Del último vector a una probabilidad por token

Tras el último bloque, cada posición tiene un vector de \(d_{model}\) números. Para predecir el siguiente token se toma el vector de la última posición, se multiplica por una matriz \(d_{model} \times V\) (donde \(V\) es el tamaño del vocabulario) y salen \(V\) números sueltos llamados logits. Una softmax (módulo 1) los convierte en probabilidades que suman 1. En GPT-2, \(V = 50.257\) tokens.

Ejemplo numérico

El modelo ve «El detective persigue al…» y, para simplificar, solo considera cuatro candidatas. Logits (cifras inventadas): ladrón = 2, asesino = 1, fantasma = 0, dragón = −1.

  1. Exponenciales: \(e^{2} = 7{,}389\), \(e^{1} = 2{,}718\), \(e^{0} = 1\), \(e^{-1} = 0{,}368\). Suma \(= 11{,}475\).
  2. Probabilidades: \(7{,}389/11{,}475 = 0{,}644\); \(2{,}718/11{,}475 = 0{,}237\); \(1/11{,}475 = 0{,}087\); \(0{,}368/11{,}475 = 0{,}032\). Suman 1.

Cómo se entrena: acertar el siguiente token

Se toma texto real, se esconde el siguiente token y se le pide al modelo que lo prediga. La pérdida es el logaritmo negativo de la probabilidad que el modelo dio al token correcto:

\[ \text{pérdida} = -\ln p_{\text{correcto}} \]
  • Si dio \(p = 0{,}9\) a la palabra correcta: pérdida \(= -\ln 0{,}9 = 0{,}105\) (casi nada: acertó).
  • Si dio \(p = 0{,}2\): pérdida \(= 1{,}609\).
  • Si dio \(p = 0{,}01\): pérdida \(= 4{,}605\) (mucho: casi ni lo consideraba).
  • Un modelo que no sabe nada y reparte por igual entre 50.257 tokens tiene pérdida \(\ln 50.257 = 10{,}825\).

Es la misma entropía cruzada del módulo 1. La perplejidad es \(e^{\text{pérdida media}}\): con pérdida 1,609 la perplejidad es 5, es decir, el modelo duda como si tuviera que elegir entre 5 palabras igual de probables.

Gracias a la máscara causal, una sola pasada por una frase entrena muchas predicciones a la vez. Con el subtítulo «El detective corre rápido» se aprenden tres ejemplos en paralelo: «El» → detective; «El detective» → corre; «El detective corre» → rápido. Ninguno puede espiar su propia respuesta, porque cada posición solo ve a las anteriores.

Preentrenamiento, ajuste y alineación (la idea general)

  1. Preentrenamiento: predecir el siguiente token sobre cantidades enormes de texto. Aquí el modelo aprende gramática, datos del mundo, estilos y patrones de razonamiento como efecto secundario de predecir bien.
  2. Ajuste fino con ejemplos (fine-tuning): se sigue entrenando con ejemplos de conversaciones o instrucciones bien resueltas, para que responda en lugar de limitarse a continuar el texto.
  3. Alineación con preferencias humanas (por ejemplo, RLHF: aprendizaje por refuerzo a partir de valoraciones humanas): personas comparan respuestas y se entrena al modelo para preferir las mejores.

Es el esquema general publicado. Los detalles exactos de los modelos comerciales más recientes no son públicos, así que no los afirmo aquí.

Elegir el siguiente token: temperatura, top-k y top-p

El modelo no da «la palabra»; da una distribución. Qué hacer con ella es decisión nuestra, y cambia mucho el resultado:

  • Voraz (greedy): siempre la más probable. Es determinista y tiende a repetirse.
  • Muestreo: sortear según las probabilidades (el 64 % de las veces «ladrón», el 24 % «asesino»…). Da variedad.

Y tres botones para controlar el muestreo:

\[ p_i = \frac{e^{z_i / T}}{\sum_j e^{z_j / T}} \]
  • \(z_i\): el logit del token \(i\); \(T\): la temperatura. Con \(T < 1\) las diferencias se agrandan (el favorito gana más); con \(T > 1\) se aplanan; con \(T \to 0\) equivale a voraz; con \(T \to \infty\), a elegir al azar.
  • top-k: se descartan todas menos las \(k\) más probables y se renormaliza.
  • top-p (nucleus): se queda el grupo más pequeño de candidatas cuya probabilidad acumulada llega a \(p\) y se renormaliza.
Ejemplo numérico

Con los logits \((2, 1, 0, -1)\) de antes:

  2. top-p = 0,8: las acumuladas son 0,644 (no llega) y 0,881 (ya pasa de 0,8) → bastan 2 candidatas; el mismo resultado que top-k = 2. Con top-p = 0,95 hacen falta 3 (0,644 + 0,237 + 0,087 = 0,968).
Regla fácil

T baja → texto seguro pero repetitivo (bueno para código o datos). T alta → texto más variado pero más propenso a errores (bueno para ideas). top-k/top-p sirven para cortar la «cola» de palabras absurdas con probabilidades minúsculas antes de sortear, sin perder la variedad entre las razonables.

Por dentro: el tamaño de un GPT de verdad

Un GPT es el bloque Transformer repetido muchas veces, más una capa de embeddings de entrada (token + posición) y la proyección final a \(V\) logits. GPT-2 pequeño (publicado por OpenAI en 2019) tiene 12 bloques, \(d_{model} = 768\), 12 cabezas, contexto de 1.024 tokens y \(V = 50.257\). Con lo que has aprendido puedes contar sus parámetros:

Es el «124 M» (124 millones) que se publica de GPT-2 pequeño. La capa final reutiliza la matriz de embeddings de tokens (se llama weight tying), así que no añade parámetros. Una regla rápida: cada bloque pesa unas \(12\,d_{model}^2\) parámetros (\(4d^2\) de atención y \(8d^2\) de feed-forward). Con ella, GPT-3 (publicado: 96 bloques, \(d_{model} = 12.288\), 96 cabezas) sale \(12 \cdot 96 \cdot 12.288^2 = 173.946.175.488\) ≈ 174 mil millones; sumando sus embeddings se acerca a los 175 mil millones publicados.

Para generar rápido, los modelos guardan las claves y valores (K y V) ya calculados de todos los tokens anteriores (la caché KV): como la máscara causal impide que los tokens pasados cambien, al añadir uno nuevo solo hay que calcular su propia Q, K y V.

BERT, la otra familia, y el ecosistema

  • BERT (2018) usa solo la parte encoder: atención sin máscara causal, donde cada token ve a izquierda y derecha. Se entrena escondiendo palabras al azar (≈ 15 %) y pidiendo adivinarlas (masked language modeling). Sirve para entender texto (clasificar, buscar, extraer entidades), no para generarlo. BERT-base tiene 12 bloques, \(d_{model} = 768\), 12 cabezas y unos 110 millones de parámetros (publicado).
  • Herramientas: lo habitual no es entrenar un Transformer desde cero, sino cargar uno preentrenado. La librería transformers de Hugging Face lo hace en una línea (por ejemplo pipeline("text-generation", model="gpt2")) y Keras tiene su propio catálogo (KerasHub). No los ejecutamos aquí porque descargan los pesos de internet; en el módulo 5 verás el uso práctico de modelos preentrenados.
Ojo: predice texto probable, no verdadero

Un GPT no consulta una base de datos de hechos: elige tokens plausibles según lo que vio al entrenar. Por eso puede inventar con total seguridad un dato, una cita o una función de una librería que no existe (a esto se le llama «alucinación»). Y como aprende de textos humanos, hereda sus sesgos. Úsalo como un colaborador rápido al que hay que verificar, no como un oráculo.

12 · Un bloque Transformer en Keras: TokenAndPositionEmbedding y TransformerBlock

Para qué sirve Construir un mini-Transformer (embedding de token + posición, un bloque de atención, pooling y clasificador), contar sus parámetros pieza por pieza y entrenarlo sobre el mismo conjunto del fragmento 5.

import numpy as np
import tensorflow as tf
from tensorflow import keras
from tensorflow.keras import layers

keras.utils.set_random_seed(42)
X = np.random.randint(1, 100, size=(1500, 20))          # mismo conjunto que el fragmento 5
y = (X.mean(axis=1) > 50).astype("int32")

class TokenAndPositionEmbedding(layers.Layer):
    """Vector del token + vector de su posición (los dos se aprenden)."""
    def __init__(self, maxlen, vocab_size, embed_dim):
        super().__init__()
        self.token_emb = layers.Embedding(input_dim=vocab_size, output_dim=embed_dim)
        self.pos_emb = layers.Embedding(input_dim=maxlen, output_dim=embed_dim)

    def call(self, inputs):
        positions = tf.range(start=0, limit=tf.shape(inputs)[-1], delta=1)    # 0, 1, 2, ..., n-1
        return self.token_emb(inputs) + self.pos_emb(positions)               # se SUMAN

class TransformerBlock(layers.Layer):
    """Atención + residual + LayerNorm, y feed-forward + residual + LayerNorm."""
    def __init__(self, embed_dim, num_heads, ff_dim):
        super().__init__()
        self.att = layers.MultiHeadAttention(num_heads=num_heads, key_dim=embed_dim // num_heads)
        self.ffn = keras.Sequential([layers.Dense(ff_dim, activation="relu"), layers.Dense(embed_dim)])
        self.norm1 = layers.LayerNormalization(epsilon=1e-6)
        self.norm2 = layers.LayerNormalization(epsilon=1e-6)

    def call(self, inputs):
        atencion = self.att(query=inputs, value=inputs, key=inputs)    # self-attention: Q = K = V = la entrada
        x = self.norm1(inputs + atencion)                               # conexión residual + normalización
        return self.norm2(x + self.ffn(x))

def transformer_demo(X, y, epochs, maxlen=20, vocab=100, embed_dim=32, heads=2, ff=64):
    inputs = keras.Input(shape=(maxlen,))
    x = TokenAndPositionEmbedding(maxlen, vocab, embed_dim)(inputs)
    x = TransformerBlock(embed_dim, heads, ff)(x)
    x = layers.GlobalAveragePooling1D()(x)                              # (n, 20, 32) -> (n, 32): promedio sobre los tokens
    x = layers.Dense(32, activation="relu")(x)
    outputs = layers.Dense(1, activation="sigmoid")(x)
    model = keras.Model(inputs, outputs)
    model.compile(optimizer="adam", loss="binary_crossentropy", metrics=["accuracy"])
    hist = model.fit(X, y, epochs=epochs, batch_size=32, validation_split=0.2, verbose=0)
    return model, hist

model, hist = transformer_demo(X, y, epochs=5)
model.summary()
print("5 épocas  -> accuracy entreno:", round(hist.history["accuracy"][-1], 3),
      "| validación:", round(hist.history["val_accuracy"][-1], 3))
model30, hist30 = transformer_demo(X, y, epochs=30)
print("30 épocas -> accuracy entreno:", round(hist30.history["accuracy"][-1], 3),
      "| validación:", round(hist30.history["val_accuracy"][-1], 3))

14 · Cómo se elige la siguiente palabra: temperatura, top-k, top-p y un modelo de juguete

Para qué sirve Implementar desde cero el último paso de un GPT (logits → temperatura → top-k/top-p → sorteo) y probarlo con un modelo de bigramas diminuto que se puede entender entero.

import numpy as np

def softmax(logits, T=1.0):
    z = np.asarray(logits, dtype=float) / T            # la temperatura divide los logits
    z = z - z.max()                                    # estabilidad numérica
    e = np.exp(z)
    return e / e.sum()

def filtrar(p, top_k=None, top_p=None):
    """Pone a 0 las candidatas descartadas por top-k y/o top-p, y renormaliza."""
    p = p.copy()
    orden = np.argsort(p)[::-1]                        # de más a menos probable
    if top_k is not None:
        p[orden[top_k:]] = 0.0
    if top_p is not None:
        acumulada = np.cumsum(p[orden]) / p.sum()
        corte = np.searchsorted(acumulada, top_p) + 1  # cuántas hacen falta para llegar a top_p
        p[orden[corte:]] = 0.0
    return p / p.sum()

print("top-p=0.95     :", filtrar(p1, top_p=0.95).round(3))
