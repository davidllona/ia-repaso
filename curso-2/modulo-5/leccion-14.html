Datos y ImageDataGenerator

Un dataset de imágenes no cabe en una variable como una tabla. ¿Cómo le damos a Keras 300 fotos en el formato que necesita, en trozos de 32, sin cargarlas todas a la vez?

Tres conjuntos, tres funciones

Las imágenes se reparten en tres conjuntos, cada uno en su carpeta, y dentro de cada uno una subcarpeta por clase:

aviones/
├── train/        (lo que la red usa para aprender: 150 + 150 imágenes en el ejemplo)
│   ├── crack/    grietas
│   └── dent/     abolladuras
├── valid/        (para vigilar el aprendizaje mientras entrena: 30 + 30)
│   ├── crack/
│   └── dent/
└── test/         (el examen final, que no se toca hasta el final: 30 + 30)
    ├── crack/
    └── dent/
Analogía: los apuntes, el simulacro y el examen

Train son las películas que ya has visto y puntuado: de ellas aprende Netflix tus gustos. Validation son unas cuantas que escondes mientras ajustas el recomendador, para comprobar si acierta con películas que no ha usado para aprender; según lo que veas, cambias el recomendador. Test son los estrenos del mes que guardas para el final: no se miran hasta el último momento, y si hubieras ajustado el recomendador con ellos, su acierto no te diría nada sobre lo que sabe de verdad. Por eso nunca se entrena con test.

Qué hace ImageDataGenerator(rescale=1./255)

Una imagen guarda cada píxel como un entero de 0 a 255. Las redes aprenden mejor con números pequeños, así que rescale=1./255 multiplica cada valor por \( 1/255 \): el 255 pasa a 1,0, el 128 pasa a 0,502 (\( 128/255 = 0{,}50196\ldots \)) y el 0 se queda en 0. Se crea un generador para cada conjunto: train_datagen, valid_datagen, test_datagen.

Ojo: rescale frente a preprocess_input

VGG16 se entrenó con un preprocesado propio, keras.applications.vgg16.preprocess_input: pasa de RGB a BGR y le resta a cada canal su media en ImageNet (por ejemplo, un píxel (255, 128, 0) acaba en (−103,9; 11,2; 131,3), en orden BGR, como muestra el fragmento 15). El cuaderno del proyecto, siguiendo el laboratorio, usa solo rescale=1./255. Funciona, pero conviene saber que con weights="imagenet" el preprocesado «oficial» es el otro; si cambias de uno a otro, cambia lo que ve la base.

flow_from_directory: de carpetas a lotes

flow_from_directory lee las carpetas y entrega las imágenes en lotes. Los argumentos del proyecto:

  • target_size=(224, 224): cada imagen se redimensiona a 224×224 (el tamaño que espera VGG16).
  • batch_size=32: cada «trozo» que se entrega tiene 32 imágenes.
  • class_mode='binary': dos clases, etiqueta 0 o 1 (un solo número por imagen, que combina con la sigmoide).
  • seed=seed_value: semilla del barajado, para reproducir.
  • shuffle=True en train y shuffle=False en valid y test. En train se baraja para que cada época vea las imágenes en otro orden. En valid/test no: así el orden es estable y se puede relacionar la imagen número i con su etiqueta real y su predicción.

El mensaje Found 300 images belonging to 2 classes. significa «300 archivos en 2 carpetas»: 300 imágenes, no 300 neuronas. Las etiquetas se asignan por orden alfabético de carpeta: train_generator.class_indices es {'crack': 0, 'dent': 1}. Es decir, 1 significa «dent»: la salida de la sigmoide es la probabilidad de abolladura. Las tareas 1 y 2 son exactamente esto para valid y test (con shuffle=False). Todo el código está en el fragmento 14 (con el dataset sintético).

Batch, step y época

  • Batch: un grupo de imágenes que se procesan juntas (32), como mirar 32 pósters seguidos antes de decidir si cambias de opinión.
  • Step: una actualización de pesos; se hace una por batch.
  • Época (epoch): una pasada completa por todo el conjunto de entrenamiento (haber visto los 300 pósters una vez).
Ejemplo numérico: 300 imágenes con batch_size = 32 (300 pósters o 300 fotos de avión: la cuenta es la misma)
  1. \( 300 / 32 = 9{,}375 \): no es un número entero.
  2. Nueve batches llenos son \( 9\cdot32 = 288 \) imágenes. Quedan \( 300 - 288 = 12 \). Esas 12 forman un décimo batch, más pequeño.
  3. Por tanto hay 10 steps por época (\( \lceil 9{,}375 \rceil = 10 \)). Keras lo escribe como 1/10 … 10/10.
  4. Con n_epochs = 5 son \( 5\cdot10 = 50 \) steps (50 actualizaciones de pesos) en total.

El fragmento 14 lo confirma: len(train_generator) vale 10, el primer batch tiene forma (32, 224, 224, 3) y el último (12, 224, 224, 3).

Aumento de datos (extra: no está en el proyecto, pero conviene conocerlo)

Con pocas imágenes, una técnica clásica es el aumento de datos: en cada época se entrega una versión ligeramente modificada de cada foto (girada unos grados, desplazada, con más o menos brillo, volteada). Es como si de cada póster de Shrek tuvieras la foto un poco torcida, más oscura o recortada: la red ve «imágenes nuevas» sin que hayas sacado ninguna foto más. En ImageDataGenerator se activa con argumentos como rotation_range, width_shift_range, zoom_range, brightness_range y horizontal_flip. Solo se aplica a train: validación y test deben mostrar las imágenes tal cual, para medir con honestidad.

Ojo (Keras 3): el import clásico ya no funciona

En muchos tutoriales verás from keras.preprocessing.image import ImageDataGenerator. En Keras 3 (la versión de este módulo) falla con ImportError: cannot import name 'ImageDataGenerator' from 'keras.preprocessing.image'. Dos salidas, ambas en el fragmento 15: (a) importarlo de tensorflow.keras.preprocessing.image, la versión heredada que sigue funcionando (es la que usa este módulo), o (b) la alternativa moderna keras.utils.image_dataset_from_directory más capas Rescaling, RandomFlip y RandomRotation dentro del modelo. En el laboratorio, con las versiones fijadas del curso, el import clásico funciona.

14 · ImageDataGenerator y flow_from_directory (Tareas 1 y 2)

Para qué sirve Crear los tres generadores del proyecto (train con shuffle=True, valid y test con shuffle=False), ver el mapeo de clases, las cuentas de batches y comprobar el efecto de rescale. Necesita las carpetas del fragmento 13.

import numpy as np
import random
import tensorflow as tf
from tensorflow.keras.preprocessing.image import ImageDataGenerator

seed_value = 42
random.seed(seed_value); np.random.seed(seed_value); tf.random.set_seed(seed_value)

batch_size = 32
img_rows, img_cols = 224, 224
train_dir, valid_dir, test_dir = "aviones_sinteticos/train", "aviones_sinteticos/valid", "aviones_sinteticos/test"

train_datagen = ImageDataGenerator(rescale=1./255)
valid_datagen = ImageDataGenerator(rescale=1./255)
test_datagen = ImageDataGenerator(rescale=1./255)

train_generator = train_datagen.flow_from_directory(
    train_dir, target_size=(img_rows, img_cols), batch_size=batch_size,
    seed=seed_value, class_mode="binary", shuffle=True)
valid_generator = valid_datagen.flow_from_directory(
    directory=valid_dir, class_mode="binary", seed=seed_value,
    batch_size=batch_size, shuffle=False, target_size=(img_rows, img_cols))
test_generator = test_datagen.flow_from_directory(
    directory=test_dir, class_mode="binary", seed=seed_value,
    batch_size=batch_size, shuffle=False, target_size=(img_rows, img_cols))

print("class_indices:", train_generator.class_indices)
print("batches por época:", len(train_generator), "= ceil(300 / 32) =", -(-300 // 32))
x, y = next(train_generator)
print("primer batch:", x.shape, y.shape, "| etiquetas:", y[:8])
print("valores de píxel: mínimo %.2f, máximo %.2f" % (x.min(), x.max()), "| tipo:", x.dtype)
print("último batch:", train_generator[len(train_generator) - 1][0].shape)
print("valid, primeros nombres:", valid_generator.filenames[:2], "... y los últimos:", valid_generator.filenames[-1])
print("rescale: 255 ->", 255 * (1. / 255), "| 128 ->", round(128 * (1. / 255), 3))
