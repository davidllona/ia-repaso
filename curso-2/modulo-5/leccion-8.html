Un 90 % de acierto no basta: mira la brecha de las curvas y la matriz de confusión

Entrenar es fácil; saber si ha aprendido, no tanto. Las curvas de train y valid dicen si memoriza, y la matriz de confusión dice en qué se equivoca.

Índice del módulo

Tu modelo acierta el 99 % en train y el 70 % en valid. ¿Ha aprendido bien?

No: está sobreajustando. Memoriza las fotos de entrenamiento sin generalizar, como aprenderte de memoria las películas que ya viste sin entender tus gustos. Lo que delata el problema es la brecha entre las dos curvas.

Entrenar, mirar las curvas, contar los errores

compile no entrena: elige la pérdida (binary_crossentropy), el optimizador (Adam(0.0001)) y la métrica (accuracy). fit entrena y guarda en history cuatro listas, un valor por época: loss, accuracy, val_loss y val_accuracy.

Pero la accuracy no dice qué errores comete. Para eso se cuenta cada combinación de clase real y predicha: la matriz de confusión.

La parte 2 del proyecto usa BLIP, un preentrenado multimodal (visión + lenguaje) que se usa tal cual, sin entrenar, para escribir una frase sobre la foto. Lo tienes en «Profundizar», con el error real del laboratorio.

Dos modelos aciertan las mismas 60 fotos. Uno responde siempre \( p = 0{,}51 \) a la clase correcta; el otro, \( p = 0{,}99 \). ¿Tienen la misma pérdida?

No. Los dos tienen un 100 % de accuracy, pero la pérdida del primero es \( -\ln 0{,}51 = 0{,}673 \), casi la de adivinar (0,693), y la del segundo, \( -\ln 0{,}99 = 0{,}010 \). La accuracy cuenta aciertos; la pérdida mide cuánta confianza pones en ellos.

En tres líneas

  • compile configura (pérdida, optimizador, métrica); fit entrena y deja el history.
  • Brecha grande entre train y valid = sobreajuste; las dos bajas = infraajuste.
  • La matriz de confusión enseña qué error comete; el umbral decide cuál prefieres.

Compilar y entrenar: compile, fit, history

Tarea 4: compile

model.compile(optimizer=Adam(learning_rate=0.0001), loss='binary_crossentropy', metrics=['accuracy']). No entrena nada: configura tres cosas.

  • Cómo medir el error (loss): binary_crossentropy, la pérdida de la clasificación binaria con sigmoide.
  • Cómo corregir los pesos (optimizer): Adam con paso 0,0001 (el mismo valor se escribe también 1e-4).
  • Qué métricas enseñar (metrics): la accuracy (proporción de aciertos) para que la leas tú.
Ejemplo numérico: la entropía cruzada binaria, a mano

Para una imagen con etiqueta real \( y \) y probabilidad predicha \( p \) (de clase 1):

\[ L = -\big[\, y\,\ln p + (1-y)\,\ln(1-p) \,\big] \]
  • Etiqueta \( y=1 \) y \( p = 0{,}88 \) (acierta con confianza): \( L = -\ln 0{,}88 = \) 0,128.
  • Etiqueta \( y=1 \) y \( p = 0{,}12 \) (se equivoca con confianza): \( L = -\ln 0{,}12 = \) 2,120. Una pérdida unas 16,6 veces mayor.
  • Etiqueta \( y=0 \) y \( p = 0{,}12 \): \( L = -\ln(1-0{,}12) = -\ln 0{,}88 = \) 0,128.

Dicho con Netflix: si el recomendador te dijo «88 % de que te encantará» y te encantó, casi no se «castiga»; si te dijo «12 %» y te encantó, el castigo es 16 veces mayor: se penaliza más estar muy seguro y equivocarse. El fragmento 12 comprueba estas cuentas, incluida la de Keras (keras.losses.binary_crossentropy también da 0,128).

Ojo: pérdida (loss) no es precisión (accuracy)

Dos modelos pueden acertar las mismas imágenes y tener pérdidas muy distintas. Si el primero responde siempre \( p = 0{,}51 \) a la clase correcta, su accuracy es 100 % pero su pérdida es \( -\ln 0{,}51 = 0{,}673 \) (casi la de adivinar: \( -\ln 0{,}5 = 0{,}693 \)). Si el segundo responde \( p = 0{,}99 \), el accuracy es el mismo y la pérdida es \( -\ln 0{,}99 = 0{,}010 \). La accuracy solo cuenta aciertos; la pérdida mide cuánta confianza pones en ellos. Mira las dos.

Tarea 5: fit y history

history = model.fit(train_generator, epochs=n_epochs, validation_data=valid_generator). Aquí sí se entrena: n_epochs = 5 pasadas, y al final de cada una, se evalúa en validación. train_history = model.history.history es un diccionario con cuatro claves: loss, accuracy, val_loss y val_accuracy, cada una con una lista de valores, uno por época (el fragmento 16 lo imprime). Recuerda: CPU frente a GPU

VGG16 con imágenes de 224×224 en la CPU es lento: cada época tiene que pasar 300 imágenes por 13 capas convolucionales grandes. Una GPU (la tarjeta gráfica, hecha para multiplicar matrices en paralelo) lo acelera muchísimo. Si tu entorno no tiene GPU, bájale el tamaño de imagen o usa menos imágenes mientras pruebas el código.

Regla fácil

Mira la brecha entre train y valid. Brecha pequeña y notas altas: bien. Brecha grande: sobreajuste (más datos, más Dropout, aumento de datos, menos capas entrenables). Las dos bajas: infraajuste (más épocas, otro learning rate, más capacidad).

Parte 2: describir la imagen con BLIP

VGG16 solo dice «dent» o «crack». ¿Cómo se consigue que el sistema escriba una frase como «this is a detailed photo showing the damage…»?

BLIP es un modelo preentrenado multimodal: entiende a la vez visión y lenguaje. Es como quien escribe la sinopsis de una película mirando solo el póster. Está construido sobre Transformers (la arquitectura de atención con consultas, claves y valores, \( Q \), \( K \), \( V \), que verás con calma en el módulo 4) y puede relacionar una imagen con texto y generar texto. A diferencia de VGG16, aquí no entrenamos nada: lo usamos tal cual. Es el segundo uso de un preentrenado: (1) extraer características y poner mi propia cabeza (VGG16), (2) usarlo directamente (BLIP).

Una nota importante: este código no se ha ejecutado aquí

BLIP necesita PyTorch, la librería transformers y descargar el modelo de internet. En el entorno donde se ha escrito este módulo no había ninguna de las tres cosas, así que el fragmento 20 es «código del curso, no ejecutado aquí» y por eso no muestra ninguna salida inventada. Para poder explicar igualmente las partes de Keras/TensorFlow que lo rodean (la capa personalizada, tf.constant, .numpy().decode) el fragmento 19 usa una capa idéntica en estructura con un sustituto de BLIP, y sí está ejecutado.

Los dos objetos de BLIP: processor y model

  • processor: prepara lo que BLIP necesita (convierte la imagen y el texto de entrada en tensores, y al final convierte los números de salida en texto legible).
  • model: el modelo BLIP propiamente dicho, que genera el texto.
Ojo: la variable model cambia de significado

En la parte 1, model era el clasificador VGG16 + Dense. En la parte 2, la misma palabra model pasa a ser BLIP. El nombre de una variable no define el objeto: manda la última asignación ejecutada. Si después de cargar BLIP vuelves a ejecutar test_model_on_image(test_generator, model, …), estarás pasando BLIP al clasificador y fallará de forma rara. Mejor nombres distintos (clf_model y blip_model).

La capa personalizada BlipCaptionSummaryLayer

Keras tiene capas como Dense, Dropout, Flatten. Pero «abre un archivo, prepara la imagen, llama a un modelo de PyTorch y devuelve texto» no cabe en ninguna. Se escribe una capa personalizada (una clase que hereda de Layer) que encapsula esa lógica: recibe la ruta de la imagen y una tarea ("caption" o "summary") y devuelve el texto. Su interior exacto lo trae el cuaderno del laboratorio y puede variar en detalles; esta es la estructura típica (la misma que usan los fragmentos 19 y 20), en cuatro pasos:

  1. tf.py_function(self.process_image, [image_path, task], tf.string) deja que TensorFlow llame a una función de Python normal (la que usa PyTorch) y espera que devuelva un string.
  2. Dentro, image_path.numpy().decode("utf-8") saca la ruta como texto Python, y Image.open(...).convert("RGB") abre la imagen.
  3. Según la tarea elige un prompt (el arranque de la frase): "this is a picture of" para el caption, "this is a detailed photo showing" para el summary.
  4. El processor prepara la entrada, model.generate(...) genera y processor.decode(...) convierte los números en frase.

Caption es la descripción breve; summary, la más detallada. En el laboratorio, el summary de una foto de avión salió con una frase parecida a «this is a detailed photo showing the damage to the fuselage of the aircraft» (ejemplo de las notas; el texto exacto puede variar de una ejecución a otra).

  • Tarea 9: caption = generate_text(image_path, tf.constant("caption")) y print("Generated Caption:", caption.numpy().decode("utf-8")).

Tensores, tf.constant, .numpy() y .decode

Un tensor es una estructura numérica con cualquier número de ejes: un escalar (0 ejes), un vector (1), una matriz (2), una imagen RGB (3: alto, ancho, canales). tf.constant("caption") crea un tensor constante que contiene la cadena; tf.py_function pide los datos como tensores, no como str. Lo que hay que saber para recuperar el texto:

  1. La salida de la capa es un tensor de TensorFlow (EagerTensor) de tipo string.
  2. .numpy() lo saca del mundo TF; un string de TF queda como bytes: b'this is a detailed photo…' (la b delante indica bytes, no texto).
  3. .decode("utf-8") convierte esos bytes en un str normal de Python.
El error real del laboratorio: AttributeError: 'str' object has no attribute 'numpy'

Lo que pasó: generate_text terminaba con return output.numpy().decode("utf-8"), es decir, ya devolvía un str. Luego, el código de las tareas 9 y 10 volvía a hacer caption.numpy().decode("utf-8")… sobre un str. Un str de Python no tiene método .numpy(), de ahí el error. Lo mismo que pelar una naranja dos veces. La solución: que generate_text haga return output (el tensor) y convertir una sola vez, fuera. Los dos casos se reproducen en el fragmento 19, con salidas reales: el primero imprime str -> … y el AttributeError con ese mensaje exacto; el segundo muestra EagerTensor, los bytes b'…' y, tras .decode, el texto.

Cierre del curso: lo que hay que quedarse

El módulo tiene dos ideas que dan mucho de sí:

  • Un autoencoder aprende, sin etiquetas, una representación comprimida de tus datos (la carátula resumida en pocos números); si se entrena con ruido como entrada y la imagen limpia como objetivo, aprende a quitarlo; no es una RBM, y a veces PCA basta.
  • Un modelo preentrenado (el crítico que ya ha visto miles de películas) reutiliza lo que otros aprendieron con muchísimos datos: lo congelas, le pones una cabeza nueva y, si hace falta y con un learning rate muy pequeño, descongelas algunas capas altas.

Resumen de todo el módulo

  • Autoencoder: red que aprende a comprimir y reconstruir su entrada: entrada → encoder → bottleneck → decoder → reconstrucción. Entrada = objetivo (fit(X, X)), por eso no necesita etiquetas. Se entrena con MSE y Adam como cualquier red. Intenta aproximar la identidad, pero el pasillo estrecho le obliga a aprender estructura; el código no es una foto pequeña. Es específico de sus datos (comprimir bien carátulas de terror no implica comprimir bien las de dibujos animados). Idea de fondo: describir un póster en 30 segundos y que otro lo dibuje.
  • Cuentas: 784 → 128 → 32 → 128 → 784 tiene 209.968 parámetros (100.480 + 4.128 + 4.224 + 101.136) y comprime 24,5 veces. El convolucional de las notas (Conv16, MaxPool, Conv8, MaxPool «bottleneck» 7×7×8 = 392, Conv8, UpSampling, Conv16, UpSampling, Conv1 sigmoide) tiene 3.217 y comprime solo 2 veces. padding="same" conserva el tamaño; con imágenes impares la salida deja de coincidir (25 → 28).
  • Denoising: entrada ruidosa, objetivo limpio. ruido = normal(0, 0,25) y np.clip a [0, 1] (el recorte sube la media de los negros a ≈ 0,10 y el error a ≈ 0,031). 8 épocas son pocas: con 48 el error de validación baja a 0,002.
  • Autoencoder o PCA: PCA es lineal, rápido y la primera referencia; un autoencoder lineal ≈ PCA; con activaciones no lineales captura curvas (8 números sobre dígitos: 0,0240 frente a 0,0161). No siempre es mejor. Las RBM son otro modelo (aprenden la distribución de los datos: equilibrar clases, rellenar valores que faltan, extraer características).
  • Preentrenados: redes ya entrenadas con datasets enormes (VGG16 + ImageNet): el crítico que ya ha visto miles de películas y solo aprende tu género. Capas iniciales: bordes y colores; intermedias: texturas y formas; profundas: patrones específicos. VGG16 sin top (include_top=False): 13 convoluciones + 5 pooling, 14.714.688 parámetros, salida 7×7×512 = 25.088; con top, 138.357.544.
  • Congelar (trainable=False): los pesos no se actualizan, la capa sigue en el forward. Tres escenarios: (1) feature extraction, (2) transfer learning (base congelada + cabeza nueva), (3) fine-tuning (descongelar capas superiores con Adam(1e-5)). En Keras 3, base_model.trainable = True puede no hacer nada tras congelar capa a capa, y hay que recompilar tras cambiar trainable.
  • Proyecto final: ImageDataGenerator(rescale=1./255) (255 → 1,0; 128 → 0,502) y flow_from_directory (224×224, batch 32, class_mode='binary', shuffle=True en train y False en valid/test; class_indices = {'crack': 0, 'dent': 1}). 300/32 = 9,375 → 10 steps (el último con 12). Cabeza: Dense 512 → Dropout 0,3 → Dense 512 → Dropout 0,3 → Dense 1 sigmoide (13.108.737 entrenables de 27.823.425); compile con Adam(0.0001), binary_crossentropy; loss ≠ accuracy; curvas: sano, overfitting (99 % / 70 %) o underfitting (55 % / 53 %); matriz de confusión y umbral.
  • BLIP: modelo multimodal basado en Transformers que se usa sin entrenar. processor + model dentro de una capa personalizada; tf.constant("caption") / ("summary"); la salida es un tensor: .numpy().decode("utf-8") una sola vez (si no, AttributeError: 'str' object has no attribute 'numpy'). Cuidado: la variable model pasa de clasificador a BLIP. VGG16 = CNN que clasifica con tu cabeza; BLIP = multimodal que genera texto.
  • Entorno: seed_value is not defined = celda sin ejecutar (estado del kernel); [*] = celda ejecutándose; VGG16 en CPU es lento; en Keras 3 el ImageDataGenerator se importa de tensorflow.keras.preprocessing.image.

Para qué sirve Reproducir las tareas 4 a 6 del proyecto (compilar, entrenar, leer history) y la evaluación en test con una matriz de confusión, usando el dataset sintético y una CNN pequeña de 64×64 en lugar de VGG16 para que corra en segundos. La estructura es la del proyecto (misma cabeza Dense 512 → Dropout 0.3 → Dense 512 → Dropout 0.3 → Dense 1). Necesita las carpetas del fragmento 13.

import numpy as np
import random
import tensorflow as tf
import keras
from keras import layers
from keras.optimizers import Adam
from tensorflow.keras.preprocessing.image import ImageDataGenerator
from sklearn.metrics import confusion_matrix

seed_value = 42
random.seed(seed_value); np.random.seed(seed_value); tf.random.set_seed(seed_value)
batch_size, n_epochs = 32, 10
img_rows, img_cols = 64, 64                    # 64 en vez de 224 para que corra en segundos

def generador(carpeta, mezclar):
    return ImageDataGenerator(rescale=1./255).flow_from_directory(
        "aviones_sinteticos/" + carpeta, target_size=(img_rows, img_cols), batch_size=batch_size,
        class_mode="binary", shuffle=mezclar, seed=seed_value, interpolation="bilinear")

train_generator = generador("train", True)
valid_generator = generador("valid", False)
test_generator = generador("test", False)

# Una base convolucional pequeña (sin pesos ImageNet) en lugar de VGG16
base_model = keras.Sequential([
    keras.Input(shape=(img_rows, img_cols, 3)),
    layers.Conv2D(16, 3, activation="relu"), layers.MaxPooling2D(2),
    layers.Conv2D(32, 3, activation="relu"), layers.MaxPooling2D(2),
    layers.Conv2D(32, 3, activation="relu"), layers.MaxPooling2D(2),
    layers.Flatten(),
])

Para qué sirve Ejecutar la estructura de transfer_learning_demo de las notas: base congelada, modelo con preprocess_input y GlobalAveragePooling2D, y fine-tuning de las últimas cuatro capas con Adam(1e-5). import numpy as np
import keras
from keras import layers
from keras.applications import VGG16
from keras.applications.vgg16 import preprocess_input
from keras.optimizers import Adam

def contar(modelo):
    entrenables = sum(int(np.prod(w.shape)) for w in modelo.trainable_weights)
    congelados = sum(int(np.prod(w.shape)) for w in modelo.non_trainable_weights)
    return entrenables, congelados

def transfer_learning_demo(weights=None):
    keras.utils.set_random_seed(42)
    base_model = VGG16(weights=weights, include_top=False, input_shape=(224, 224, 3))
    base_model.trainable = False

    imagenes = np.random.default_rng(0).uniform(0, 255, size=(2, 224, 224, 3)).astype("float32")
    features = base_model.predict(preprocess_input(imagenes.copy()), verbose=0)
    print("feature maps de 2 imágenes:", features.shape)

    entrada = keras.Input(shape=(224, 224, 3))
    x = preprocess_input(entrada)
    x = base_model(x, training=False)
    x = layers.GlobalAveragePooling2D()(x)
    x = layers.Dense(256, activation="relu")(x)
    salida = layers.Dense(1, activation="sigmoid")(x)
    model = keras.Model(entrada, salida)
    model.compile(optimizer="adam", loss="binary_crossentropy", metrics=["accuracy"])
    print("transfer learning  (entrenables, congelados):", contar(model))

    base_model.trainable = True
    for layer in base_model.layers[:-4]:
        layer.trainable = False
    model.compile(optimizer=Adam(1e-5), loss="binary_crossentropy", metrics=["accuracy"])
    print("fine-tuning        (entrenables, congelados):", contar(model))
    print("capas de la base entrenables:", [l.name for l in base_model.layers if l.trainable])
    return model

modelo_demo = transfer_learning_demo(weights=None)

import numpy as np
import keras

# Sigmoide: cualquier número z se convierte en una probabilidad
z = np.array([-2.0, 0.0, 1.0, 2.0])
p = 1 / (1 + np.exp(-z))
print("z        :", z)
print("sigmoide :", p.round(2))

class BlipCaptionSummaryLayer(tf.keras.layers.Layer):
