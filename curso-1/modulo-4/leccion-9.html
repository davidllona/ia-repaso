HDBSCAN: DBSCAN sin elegir eps

DBSCAN usa un único radio eps para todo el mapa. ¿Qué pasa si un grupo es muy denso y otro es muy disperso? ¿Existe un eps que sirva para los dos?

El problema: densidades distintas

Imagina el mapa de gustos de una plataforma con dos clubes de fans (por ejemplo, de Harry Potter y de Star Wars): sus miembros tienen gustos casi idénticos entre sí, y los dos clubes están pegados el uno al otro (densísimos). Lejos de ellos está el público general, con gustos muy variados (disperso). Para ver el público general como un grupo necesitas un radio grande, porque sus gustos están muy separados. Pero con ese radio grande los dos clubes, que están pegados, se fusionan en uno. Y si achicas el radio para separar los clubes, el público general entero se queda en ruido. No hay ningún valor de eps que lo arregle.

La idea: probar todos los eps a la vez

HDBSCAN (Hierarchical DBSCAN) es como ejecutar DBSCAN con todos los radios posibles y quedarse, para cada zona, con el radio que mejor la describe. En lugar de un solo corte, construye una jerarquía (como el dendrograma) y luego decide qué ramas son grupos de verdad. Los pasos conceptuales son:

  1. Distancia núcleo (core distance) de cada punto: la distancia a su min_samples-ésimo vecino. Un punto en una zona densa tiene distancia núcleo pequeña; uno disperso, grande. Mide «lo aislado que está».
  2. Distancia de alcanzabilidad mutua entre dos puntos \( a \) y \( b \): \( d_{\text{mut}}(a,b)=\max\{\,\text{core}(a),\ \text{core}(b),\ d(a,b)\,\} \). Es la distancia normal, pero «inflada» si alguno de los dos está en una zona poco densa. Ejemplo: si \( \text{core}(a)=0{,}5 \), \( \text{core}(b)=2{,}0 \) y \( d(a,b)=1{,}0 \), entonces \( d_{\text{mut}}=\max\{0{,}5;\,2{,}0;\,1{,}0\}=2{,}0 \): como \( b \) está en una zona dispersa, para conectar con él hay que «pagar» su aislamiento aunque \( a \) esté a solo 1,0.
  3. Jerarquía: con esas distancias se van uniendo los puntos de más cerca a más lejos, igual que en el clustering jerárquico con enlace single. Cada altura de corte equivale a un eps distinto de DBSCAN, así que el árbol contiene a la vez todos los resultados posibles de DBSCAN.
  4. Condensar: se recorre el árbol hacia abajo y solo se considera un «grupo nuevo» cuando una rama se divide en dos partes que tienen cada una al menos min_cluster_size puntos (usuarios). Si se desprenden trozos más pequeños, se interpreta que son puntos que se van cayendo del grupo (ruido), no grupos nuevos.
  5. Seleccionar por estabilidad: se mide cuánto «sobrevive» cada grupo candidato (durante cuántos valores de eps sigue existiendo y con cuántos puntos). Se eligen los grupos más estables, evitando contar un grupo y sus sub-grupos a la vez. Lo que no cae en ningún grupo estable es ruido (-1).
Analogía

Es como ver el catálogo desde lejos y acercarte poco a poco. Desde muy lejos solo ves una mancha («películas»). A media distancia se separan los grandes géneros. Muy cerca se ven las sagas. HDBSCAN recorre todas las distancias y se queda con los grupos que siguen reconociéndose como una unidad durante un buen rato mientras te acercas (los estables), no con los que aparecen y se rompen enseguida.

Los parámetros

  • min_cluster_size (por defecto 5): el tamaño del grupo más pequeño que consideras real. Es el parámetro que más importa y el más fácil de razonar («un tipo de espectador de menos de 15 usuarios no me sirve»).
  • min_samples (por defecto igual a min_cluster_size): lo «conservador» que es. Más alto → más puntos descartados como ruido y grupos más compactos.
  • cluster_selection_epsilon (por defecto 0): si lo subes, no separa grupos más cercanos que ese valor (útil para evitar demasiados microgrupos).
  • cluster_selection_method: "eom" (por defecto, grupos grandes y estables) o "leaf" (grupos más pequeños y numerosos, las hojas del árbol).
  • allow_single_cluster: si es True, permite que todo el conjunto sea un único grupo (por defecto no).
  • .probabilities_ (atributo): para cada punto, un número entre 0 y 1 con la «fuerza de pertenencia» a su grupo (0 para el ruido): 1 = en el corazón del grupo, cerca de 0 = en la orilla.

Ojo

Aviso de versión. HDBSCAN entró en scikit-learn en la versión 1.3 (from sklearn.cluster import HDBSCAN; antes solo existía el paquete externo hdbscan). En la 1.9 que usamos aparece un FutureWarning sobre el parámetro copy (su valor por defecto cambiará en la 1.10): se silencia pasándolo explícitamente, HDBSCAN(copy=True), como hacemos en el código. Y recuerda: min_samples cuenta de forma distinta a DBSCAN en algunos detalles, así que no esperes que HDBSCAN(min_samples=5) reproduzca exactamente a DBSCAN(min_samples=5) para algún eps; se parecen en la idea, no en el cálculo punto a punto.

11 · DBSCAN: elegir eps con la distancia al k-ésimo vecino y ejecutarlo

Para qué sirve Ver el flujo completo de DBSCAN sobre dos lunas: calcular la gráfica de k-distancias para elegir eps, ejecutar el algoritmo, leer ruido y núcleos, y compararlo con K-Means.

import numpy as np
from sklearn.cluster import DBSCAN, KMeans
from sklearn.datasets import make_moons
from sklearn.metrics import adjusted_rand_score
from sklearn.neighbors import NearestNeighbors

X, y = make_moons(n_samples=300, noise=0.07, random_state=42)

# 1) Elegir eps con la distancia al k-ésimo vecino (k = min_samples)
min_samples = 5
vecinos = NearestNeighbors(n_neighbors=min_samples).fit(X)
distancias, _ = vecinos.kneighbors(X)
k_dist = np.sort(distancias[:, -1])
print("distancia al 5.º vecino, percentiles 50/90/95/99:", np.percentile(k_dist, [50, 90, 95, 99]).round(3))

# 2) Ejecutar DBSCAN
db = DBSCAN(eps=0.15, min_samples=min_samples).fit(X)
etiquetas = db.labels_
print("Grupos encontrados:", len(set(etiquetas) - {-1}))
print("Puntos de ruido (etiqueta -1):", int((etiquetas == -1).sum()))
print("Puntos núcleo:", len(db.core_sample_indices_), "de", len(X))
print("DBSCAN   ARI =", round(adjusted_rand_score(y, etiquetas), 3))

# 3) Comparación con K-Means
km = KMeans(n_clusters=2, n_init=10, random_state=0).fit(X)
print("K-Means  ARI =", round(adjusted_rand_score(y, km.labels_), 3))

13 · HDBSCAN frente a DBSCAN con densidades distintas

Para qué sirve Ver con números por qué un solo eps no puede con grupos de densidades distintas y cómo HDBSCAN lo resuelve sin fijar eps.

import numpy as np
from sklearn.cluster import DBSCAN, HDBSCAN

# Tres grupos de densidades muy distintas (dos densos y pegados, uno disperso) + ruido
rng = np.random.default_rng(5)
A = rng.normal([3.0, 3.4], 0.2, (55, 2))
B = rng.normal([4.8, 3.4], 0.2, (55, 2))
C = rng.normal([11.5, 6.4], 1.5, (60, 2))
ruido = np.c_[rng.uniform(0.3, 15.7, 16), rng.uniform(0.3, 9.7, 16)]
X = np.vstack([A, B, C, ruido])
y = np.r_[np.zeros(55), np.ones(55), 2 * np.ones(60), 3 * np.ones(16)]

def etiqueta_dominante(lab):
    """Etiqueta más frecuente dentro de cada grupo real (A, B, C): -1 significa «ruido»."""
    return [int(np.bincount(lab[y == g] + 1).argmax()) - 1 for g in range(3)]

print("DBSCAN con distintos eps (min_samples=5):")
for eps in (0.3, 0.5, 1.0, 1.5):
    lab = DBSCAN(eps=eps, min_samples=5).fit_predict(X)
    print(f"  eps={eps}: {lab.max() + 1} grupos, {(lab == -1).sum():3d} de ruido, etiqueta de A, B, C = {etiqueta_dominante(lab)}")

hdb = HDBSCAN(min_cluster_size=15, copy=True).fit(X)
lab = hdb.labels_
print("HDBSCAN (sin eps):", lab.max() + 1, "grupos,", (lab == -1).sum(), "de ruido, etiqueta de A, B, C =", etiqueta_dominante(lab))
print("Tamaño de cada grupo:", np.bincount(lab[lab >= 0]))
print("Confianza (probabilities_), mínimo / media:", hdb.probabilities_.min().round(2), hdb.probabilities_.mean().round(2))
