Pipeline y ColumnTransformer: la forma segura de encadenar pasos

Para entrenar necesitas rellenar huecos, escalar los números, convertir el texto en columnas y, por fin, entrenar el modelo. Cada paso tiene su fit y su transform. ¿Cómo evitas liarte (y hacer leakage) cuando tienes que repetirlo en cada fold de la validación cruzada?

Un Pipeline es una cadena de pasos que se comporta como un único modelo. Todos los pasos menos el último son transformadores (tienen fit y transform: imputador, escalador, codificador…); el último es el estimador (el modelo, con fit y predict).

  • pipe.fit(X_tr, y_tr): para cada transformador hace fit_transform con el train y pasa el resultado al siguiente; el último paso entrena con lo que le llega.
  • pipe.predict(X_nuevo): aplica transform en cadena (con lo aprendido en train) y al final predice.
  • cross_val_score(pipe, X, y): en cada fold reajusta la cadena completa solo con el train de ese fold. Aquí es donde el pipeline impide el leakage del preprocesado.
Analogía

Una cadena de montaje con una receta fija. La receta (los pasos) se escribe una sola vez; cada pieza que entra por el principio sale por el final siempre tratada igual, y lo que aprende la cadena (cuánto vale la media, qué categorías existen) lo aprende solo observando la primera tanda de piezas. Si metes una pieza nueva, la cadena no «reaprende» nada: aplica lo que ya sabe.

ColumnTransformer: un tratamiento distinto por tipo de columna

Las columnas numéricas y las de texto necesitan tratamientos distintos. Es el mismo preprocesado que hicimos a mano en el módulo 1, ahora en una pieza reutilizable.

Qué vive dentro del pipeline: el repaso del módulo 1

Todo lo que aprendiste a preparar en el módulo 1 son pasos del pipeline. Casi todos «aprenden» algo de los datos (una mediana, una media, una lista de categorías), y por eso deben hacer fit solo con el train:

Tres ventajas que lo resumen todo: (1) se aplican exactamente las mismas transformaciones a train y a test (y a los datos nuevos del futuro); (2) hay menos riesgo de leakage, porque el fit de cada paso ocurre solo con el train de cada fold; (3) la búsqueda de hiperparámetros es fácil, porque se le pasa el pipeline entero a GridSearchCV.

Nombrar los hiperparámetros dentro de un pipeline

Para cambiar un parámetro de un paso se usa el nombre del paso, dos guiones bajos y el parámetro: clf__C es el C del paso clf. Con anidación se encadenan: pre__num__imp__strategy es la estrategia del imputador (imp) del bloque numérico (num) del preprocesador (pre). Este patrón lo usarás en la búsqueda de hiperparámetros. pipe.get_params() lista todos los nombres disponibles.

Ojo

handle_unknown="ignore" en OneHotEncoder es importante: si en test aparece una categoría que no existía en train (un país nuevo), el codificador por defecto lanza un error; con "ignore" pone todo a ceros. Y por defecto el ColumnTransformer descarta las columnas que no mencionas (remainder="drop"): si olvidas una, desaparece sin avisar. Pon remainder="passthrough" si quieres conservarlas tal cual.

Ojo

Pipeline([...]) exige nombrar los pasos; make_pipeline(...) los nombra solo con el nombre de la clase en minúsculas (standardscaler, logisticregression). Para el diagnóstico en pantalla y la búsqueda de hiperparámetros suele ser más cómodo Pipeline con nombres cortos. En ambos casos: divide primero los datos, construye el pipeline y llama a fit solo con el train. Y si re-muestreas clases (SMOTE), el re-muestreo también debe ir dentro de la validación cruzada, con el Pipeline de imbalanced-learn.

13 · Data leakage: la métrica «demasiado buena» y cómo evitarla con un Pipeline

Para qué sirve Provocar tres fugas de datos a propósito (seleccionar variables con todas las etiquetas, una columna que contiene la respuesta y escalar con los datos de test) y ver cómo un Pipeline cierra la primera.

import numpy as np
from sklearn.feature_selection import SelectKBest, f_classif
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler

rng = np.random.default_rng(0)
X = rng.normal(size=(60, 1000))        # 60 muestras y 1000 columnas de PURO RUIDO
y = rng.integers(0, 2, size=60)        # etiquetas al azar: no hay nada que aprender

# MAL: elegimos las 10 "mejores" columnas mirando TODAS las etiquetas, y luego validamos
X_mal = SelectKBest(f_classif, k=10).fit_transform(X, y)
mal = cross_val_score(LogisticRegression(), X_mal, y, cv=5).mean()

# BIEN: la selección va dentro del Pipeline y se repite en cada fold con su train
pipe = Pipeline([("seleccion", SelectKBest(f_classif, k=10)), ("modelo", LogisticRegression())])
bien = cross_val_score(pipe, X, y, cv=5).mean()
print(f"Selección fuera de la validación : accuracy = {mal:.3f}   <- fuga, resultado falso")
print(f"Selección dentro del Pipeline    : accuracy = {bien:.3f}   <- la realidad (ruido = azar)")

# Fuga del target: una columna que ES la respuesta con un poco de ruido
fuga = y + rng.normal(0, 0.1, size=60)
X2 = np.c_[rng.normal(size=(60, 5)), fuga]
print("Con la columna que filtra el target:", cross_val_score(LogisticRegression(), X2, y, cv=5).mean().round(3))

# Fuga del escalado: la media cambia si incluyes (o no) los datos de test
tr = np.array([[10.0], [12.0], [14.0], [16.0]])
te = np.array([[30.0], [40.0]])
bien_esc = StandardScaler().fit(tr)                       # aprende solo de train
mal_esc = StandardScaler().fit(np.vstack([tr, te]))       # aprende también de test
print("train escalado BIEN:", bien_esc.transform(tr).ravel().round(2))
print("train escalado MAL :", mal_esc.transform(tr).ravel().round(2))

14 · Un dataset de clientes con huecos y texto (para los fragmentos siguientes)

Para qué sirve Fabricar una tabla sintética de clientes de una plataforma de streaming con columnas numéricas, columnas de texto y datos que faltan, como en un proyecto real. Los fragmentos 15 a 19 reutilizan este df, así que ejecuta este primero.

import numpy as np
import pandas as pd

rng = np.random.default_rng(0)
n = 1500
df = pd.DataFrame({
    "edad": rng.integers(18, 70, n).astype(float),
    "horas_mes": rng.gamma(2.0, 9.0, n).round(1),
    "dias_sin_entrar": rng.exponential(12, n).round(0),
    "plan": rng.choice(["Basic", "Standard", "Premium"], n, p=[0.5, 0.3, 0.2]),
    "pais": rng.choice(["ES", "MX", "AR", "CO"], n),
})

# El target se calcula con las columnas COMPLETAS: más días sin entrar y menos horas -> más bajas
z = (-2.2 + 0.09 * df["dias_sin_entrar"] - 0.035 * df["horas_mes"]
     + 0.8 * (df["plan"] == "Basic") - 0.8 * (df["plan"] == "Premium"))
df["baja"] = (rng.random(n) < 1 / (1 + np.exp(-z))).astype(int)

# Ahora estropeamos los datos como en la vida real: huecos
df.loc[rng.random(n) < 0.08, "edad"] = np.nan
df.loc[rng.random(n) < 0.05, "plan"] = np.nan

print(df.head(4).to_string())
print("Forma:", df.shape)
print("Huecos por columna:", df.isna().sum()[df.isna().sum() > 0].to_dict())
print("Proporción de bajas:", df["baja"].mean().round(3))

15 · Pipeline + ColumnTransformer: imputar, escalar y codificar sin fugas

Para qué sirve Montar un único objeto que prepara los datos (rellena huecos, escala las columnas numéricas y convierte las de texto con One-Hot) y entrena el modelo. Se evalúa con validación cruzada y después con el test. Usa el df del fragmento 14.

from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import roc_auc_score
from sklearn.model_selection import cross_val_score, train_test_split
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

X = df.drop(columns="baja")
y = df["baja"]
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.25, stratify=y, random_state=42)

numericas = ["edad", "horas_mes", "dias_sin_entrar"]
categoricas = ["plan", "pais"]

pre = ColumnTransformer([
    ("num", Pipeline([("imp", SimpleImputer(strategy="median")),
                      ("esc", StandardScaler())]), numericas),
    ("cat", Pipeline([("imp", SimpleImputer(strategy="most_frequent")),
                      ("ohe", OneHotEncoder(handle_unknown="ignore"))]), categoricas),
])
pipe = Pipeline([("pre", pre), ("clf", LogisticRegression(max_iter=1000))])

cv_auc = cross_val_score(pipe, X_tr, y_tr, cv=5, scoring="roc_auc")
print("AUC por fold:", cv_auc.round(3), "| media =", cv_auc.mean().round(3))

pipe.fit(X_tr, y_tr)
print("Pasos del pipeline:", list(pipe.named_steps))
print("Columnas tras preprocesar:", list(pipe[:-1].get_feature_names_out()))
print("AUC en test:", round(roc_auc_score(y_te, pipe.predict_proba(X_te)[:, 1]), 3))
