Regresión polinómica: curvas con una regresión lineal

Los usuarios abandonan menos las películas de duración media y más las muy cortas (no llegan a engancharles) o las muy largas (se les hacen eternas). El porcentaje de abandono según la duración de la película dibuja una «U». ¿Qué hace una recta con eso?

Una recta es una mala descripción de una «U»: sube en un extremo y baja en el otro sin poder doblarse. Necesitamos curvas. Y aquí viene uno de los trucos más bonitos del Machine Learning: una curva se puede ajustar con exactamente la misma regresión lineal, si inventas columnas nuevas. Para una parábola:

\[ \hat{y} = \theta_0 + \theta_1\,x + \theta_2\,x^2 \]

Mira la fórmula como una regresión múltiple en la que la «variable 1» es \( x \) y la «variable 2» es \( x^2 \), que construyes tú elevando al cuadrado la primera. Tabla de entrada original: una columna (la duración). Tabla ampliada: dos columnas (duración y duración²). Y con las columnas nuevas ya puedes usar OLS tal cual. Se llama regresión polinómica porque \( \hat{y} \) es un polinomio de \( x \).

La clave: «lineal» se refiere a los parámetros, no a x

El modelo sigue siendo lineal en los parámetros \( \theta \): cada \( \theta \) solo multiplica una columna y se suma. Que una de esas columnas sea \( x^2 \) no importa: ya viene calculada cuando llega al modelo. Por eso la regresión polinómica no es un algoritmo nuevo, es regresión lineal múltiple con una fase previa de feature engineering (módulo 1). scikit-learn lo hace con PolynomialFeatures.

Ejemplo numérico: las columnas de un polinomio de grado 3

El grado (degree) es el exponente más alto: grado 1 = recta, grado 2 = parábola, grado 3 = cúbica… Con grado 3 el modelo es \( \hat{y} = \theta_0 + \theta_1 x + \theta_2 x^2 + \theta_3 x^3 \), y cada valor de \( x \) se convierte en cuatro números: [1, x, x², x³] (el 1 es para el intercepto). Aquí \( x \) es la duración de una película en horas (2 h y 3 h) e \( \hat{y} \) el porcentaje de usuarios que la abandona.

Con unos pesos inventados \( \theta = (1,\;2,\;3,\;0{,}5) \): para \( x=2 \), \( \hat{y} = 1 + 2\cdot2 + 3\cdot4 + 0{,}5\cdot8 = 1+4+12+4 = \) 21 % de abandono; para \( x=3 \), \( \hat{y} = 1 + 6 + 27 + 13{,}5 = \) 47,5 %. El grado: cuánta flexibilidad le doy al modelo

El grado es un hiperparámetro: lo eliges tú antes de entrenar. Un polinomio de grado \( d \) tiene \( d+1 \) parámetros y puede doblarse hasta \( d-1 \) veces. Con poco grado, el modelo es demasiado rígido (underfitting): no capta la forma. Con demasiado, es tan flexible que se contorsiona para pasar cerca de cada punto, incluido el ruido (overfitting, el problema central del módulo 1). 15 · Gradient descent a mano para la regresión lineal

Para qué sirve Programar el algoritmo de descenso por gradiente, ver cómo reproduce las iteraciones a mano del ejemplo, ver el efecto de tres learning rates sobre los coches y comprobar que llega a la misma solución que LinearRegression.

def descenso_lineal(X, y, lr, n_iter):
    """Gradient descent para y_hat = theta0 + theta1 * x, minimizando el MSE."""
    theta = np.zeros(2)                      # punto de partida: theta0 = 0, theta1 = 0
    n = len(y)
    thetas, perdidas = [], []
    for _ in range(n_iter):
        error = theta[0] + theta[1] * X - y  # y_hat - y de cada ejemplo
        thetas.append(theta.copy())
        perdidas.append(np.mean(error ** 2))
        grad0 = 2 / n * np.sum(error)        # derivada del MSE respecto a theta0
        grad1 = 2 / n * np.sum(error * X)    # derivada del MSE respecto a theta1
        theta = theta - lr * np.array([grad0, grad1])
    thetas.append(theta.copy())
    perdidas.append(np.mean((theta[0] + theta[1] * X - y) ** 2))
    return thetas, perdidas

# Los números del ejemplo a mano: tres puntos que cumplen y = 2x + 1
xs = np.array([1.0, 2.0, 3.0])
ys = np.array([3.0, 5.0, 7.0])
thetas, perdidas = descenso_lineal(xs, ys, lr=0.1, n_iter=500)
for k in (0, 1, 2, 3, 500):
    print("paso %3d | theta0 = %.3f, theta1 = %.3f | MSE = %.4f" % (k, thetas[k][0], thetas[k][1], perdidas[k]))
