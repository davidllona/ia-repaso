Un modelo falla por terco (sesgo) o por nervioso (varianza)

Un recomendador que siempre se pasa por 2 horas y otro que cada vez dice una cosa distinta tienen problemas opuestos, con remedios opuestos. Aprende a distinguirlos mirando train y test.

Índice del módulo

Reentrenas un recomendador cinco veces con datos de semanas distintas. El modelo A predice 12, 13, 11, 12, 12 horas; el B, 6, 14, 9, 11, 10. La verdad son 10 horas. ¿Cuál es mejor?

Aunque B acierta de media (10), aquí A es mejor: se equivoca siempre por unas 2 horas, pero es estable; B salta de 6 a 14. Son dos tipos de error distintos: A tiene sesgo (falla en la misma dirección) y B tiene varianza (cambia con cada entrenamiento). Abajo lo medimos.

Tres piezas del error

El error de un modelo en datos nuevos se reparte en tres partes:

  • Sesgo: error sistemático. El modelo es demasiado simple («todo es una recta») y, de media, falla en la misma dirección. Es el infraajuste.
  • Varianza: inestabilidad. El modelo es tan flexible que copia las rarezas de su muestra; cada muestra da un modelo distinto. Es el sobreajuste.
  • Ruido \( \sigma^2 \): el azar de los datos. Ningún modelo baja de ahí.
\[ \text{error esperado} = \text{sesgo}^2 + \text{varianza} + \sigma^2 \]

El dilema: subir la complejidad baja el sesgo y sube la varianza. El error total dibuja una «U», y el mejor modelo está en el fondo. Cada algoritmo tiene su perilla: max_depth en árboles, K en KNN (al revés: K pequeño = complejo), C y gamma en SVM.

Poco. Train y test son parecidos y mediocres: es sesgo, el modelo se queda corto. Más datos calman la varianza, pero no le dan capacidad a un modelo demasiado simple. Prueba un modelo más flexible o mejores variables. (Esas cifras son las del árbol de profundidad 1 con 569 tumores.)

En tres líneas

  • Error = sesgo² + varianza + ruido; más complejidad baja el sesgo y sube la varianza.
  • Train y test malos y parecidos → sesgo. Train bueno, test malo → varianza.
  • Bagging ataca la varianza; boosting, el sesgo (las dos próximas lecciones).

Sesgo y varianza: por qué fallan los modelos

Cuando un recomendador de Netflix se equivoca, ¿se equivoca siempre en la misma dirección o su error cambia cada vez que lo reentrenas con datos distintos? Son dos problemas distintos, con remedios opuestos.

Hasta aquí has visto el sobreajuste como «train alto, test bajo». Ahora podemos ponerle números exactos. El error de un modelo en datos nuevos se descompone en tres partes: sesgo, varianza y ruido. Entender cuál domina te dice qué hacer para mejorarlo.

Analogía

Cuatro recomendadores intentan adivinar la nota exacta que Ana pondrá a Titanic. Cada uno lo intenta cinco veces, entrenado cada vez con datos distintos. Cada flecha de la diana es una de esas cinco predicciones; el centro es la nota real.

  • Sesgo (bias): el error sistemático. El modelo parte de suposiciones demasiado simples (por ejemplo «la relación es una recta») y, por muchos datos que le des, de media falla en la misma dirección. Se corresponde con el infraajuste.
  • Varianza (variance): la inestabilidad. El modelo es tan flexible que se adapta a las rarezas de su conjunto de entrenamiento, y cada conjunto produce un modelo distinto. Se corresponde con el sobreajuste.
  • Ruido irreducible (\( \sigma^2 \)): el azar propio de los datos (medidas imperfectas, factores que no tenemos). Ningún modelo puede bajar de ahí.
\[ \underbrace{E\big[(y-\hat f(x))^2\big]}_{\text{error esperado}} \;=\; \underbrace{\big(E[\hat f(x)]-f(x)\big)^2}_{\text{sesgo}^2} \;+\; \underbrace{E\Big[\big(\hat f(x)-E[\hat f(x)]\big)^2\Big]}_{\text{varianza}} \;+\; \underbrace{\sigma^2}_{\text{ruido}} \]

Lectura de cada símbolo: \( f(x) \) es el valor verdadero en el punto \( x \); \( \hat f(x) \) es la predicción del modelo, que cambia según el conjunto de entrenamiento; \( E[\cdot] \) significa «promedio sobre muchos conjuntos de entrenamiento distintos»; \( \sigma^2 \) es la varianza del ruido.

Ejemplo numérico

Ana verá en realidad 10 horas de series la semana que viene (valor verdadero \( f = 10 \)) y el azar de cada semana añade un ruido \( \sigma^2 = 1 \). Entrenamos dos recomendadores cinco veces, cada vez con datos distintos, y anotamos las horas que predice cada vez (cifras inventadas):

ModeloPrediccionesMediaSesgo² = (media − 10)²Varianza = media de (pred − media)²Error esperado
A (simple)12, 13, 11, 12, 1212(12 − 10)² = 4(0 + 1 + 1 + 0 + 0) / 5 = 0,44 + 0,4 + 1 = 5,4
B (flexible)6, 14, 9, 11, 1010(10 − 10)² = 0(16 + 16 + 1 + 1 + 0) / 5 = 6,80 + 6,8 + 1 = 7,8

El modelo A siempre se equivoca por unas 2 horas (mucho sesgo) pero es muy estable. El B acierta de media (sesgo 0) pero cada vez da algo muy distinto. Aquí, A tiene menos error esperado: la varianza de B pesa más que el sesgo de A. En otros problemas ocurre lo contrario; por eso hay que medirlo.

El compromiso entre sesgo y varianza

Aquí está el dilema (bias–variance trade-off): subir la complejidad del modelo baja el sesgo (puede imitar formas más complicadas) pero sube la varianza (se adapta también al ruido). Bajar la complejidad hace lo contrario. El error total suele dibujar una «U»: alto con modelos muy simples (domina el sesgo), mínimo en un punto intermedio y alto otra vez con modelos muy complejos (domina la varianza).

Cómo se ve en train y en test

En la práctica no conoces la función verdadera, así que no puedes calcular sesgo y varianza directamente. Lo que sí puedes medir es el error en train y en test, y de ahí deducir qué te pasa:

Diagnóstico a partir de los errores
SituaciónError en trainError en testDiagnósticoQué probar
Sesgo altoAltoAlto, casi igual al de trainInfraajuste: el modelo no tiene capacidadUn modelo más flexible, más variables útiles, menos regularización, boosting
Varianza altaMuy bajoMucho mayor que el de trainSobreajuste: memorizaMás datos, un modelo más simple, regularización, bagging / Random Forest, parada temprana
EquilibradoBajoUn poco mayor que el de trainGeneraliza bienYa has llegado: afina o para

Con árboles y datos simulados lo hemos medido de verdad en el fragmento 14: un árbol de 1 nivel tiene sesgo² 0,059 y varianza 0,050; uno de 8 niveles, sesgo² 0,001 y varianza 0,094. Al subir la profundidad el sesgo desaparece y la varianza crece. Y en el fragmento 3, con datos reales, el árbol de profundidad 1 tenía 0,932 en train y 0,889 en test (poca brecha, ambos mediocres: sesgo), mientras que el árbol completo marcaba 1,000 y 0,906 (brecha grande: varianza).

Regla fácil

Si train y test son malos y parecidos → sesgo (el modelo es corto). Si train es bueno y test es malo → varianza (el modelo memoriza). Más datos ayudan a la varianza, pero no arreglan el sesgo: un modelo demasiado simple no mejora por mucho que le des.

Ojo

Esta lectura sirve de guía, pero un error de test alto también puede deberse a otras causas: fuga de datos (data leakage), datos de test distintos de los de train, etiquetas ruidosas o un reparto desafortunado con pocos datos. La validación cruzada y las curvas de aprendizaje del módulo 5 te permiten distinguirlas.

Adelanto

Lo mejor de este diagnóstico es que explica los ensembles de la sección siguiente: el bagging (y el Random Forest) ataca la varianza promediando muchos modelos inestables; el boosting ataca el sesgo encadenando modelos simples que corrigen los errores de los anteriores.

Código

14 · Sesgo y varianza medidos de verdad por simulación

Para qué sirve Entrenar el mismo modelo con 200 conjuntos de datos distintos y medir con números cuánto se equivoca «de media» (sesgo²) y cuánto cambia de un entrenamiento a otro (varianza), para varias complejidades.

import numpy as np
from sklearn.tree import DecisionTreeRegressor

def verdad(x):
    return np.sin(2 * x)

x_grid = np.linspace(0, 3, 100).reshape(-1, 1)
repeticiones = 200
print("max_depth | sesgo² | varianza | sesgo² + varianza")
for profundidad in (1, 2, 4, 8):
    predicciones = []
    for r in range(repeticiones):
        rng = np.random.default_rng(r)               # un conjunto de entrenamiento distinto cada vez
        x = rng.uniform(0, 3, 40).reshape(-1, 1)
        y = verdad(x).ravel() + rng.normal(0, 0.3, 40)
        arbol = DecisionTreeRegressor(max_depth=profundidad).fit(x, y)
        predicciones.append(arbol.predict(x_grid))
    predicciones = np.array(predicciones)             # forma (200, 100)
    sesgo2 = np.mean((predicciones.mean(axis=0) - verdad(x_grid).ravel()) ** 2)
    varianza = np.mean(predicciones.var(axis=0))
    print(f"{profundidad:9d} | {sesgo2:6.3f} | {varianza:8.3f} | {sesgo2 + varianza:.3f}")
