Elegir el learning rate, y entrenar / validar / probar

El learning rate lo eliges tú antes de entrenar, y no hay una fórmula mágica. ¿Cómo se decide cuál es bueno sin engañarse a uno mismo?

Recuerda (Curso 1)

Un hiperparámetro es un ajuste que fijas tú antes de entrenar (el learning rate, las épocas, el tamaño del lote…), a diferencia de los parámetros (\( w \), \( b \)), que aprende el algoritmo. El learning rate pequeño avanza a paso de tortuga; el adecuado baja rápido; el demasiado grande rebota o diverge. Está explicado con una tabla en el Curso 1.

Analogía: buscar una escena con la barra de tiempo

Quieres llegar a tu escena favorita arrastrando la barra del reproductor. Si avanzas a saltos de 1 segundo, llegas, pero tardas una eternidad (learning rate pequeño). Si saltas de 10 minutos en 10 minutos, te pasas, vuelves, te pasas otra vez y cada vez estás más lejos de la escena (learning rate demasiado grande: diverge). El salto bueno es el más largo que todavía no se pasa de la escena.

Por qué hay un límite: el factor \( (1 - lr\cdot\lambda) \)

Con un solo parámetro y un cuenco de curvatura \( \lambda \), cada paso del descenso multiplica la distancia al fondo por \( (1 - lr\cdot\lambda) \). En un modelo con varios parámetros manda el \( \lambda \) más grande de todos (lo vimos antes: \( 2/\lambda_{\max} \)).

Elegir con validación: tres conjuntos

No puedes elegir el learning rate (ni ningún hiperparámetro) mirando el coste de entrenamiento: siempre premiará lo que mejor memorice. Los datos se parten en tres conjuntos, igual que viste en el Curso 1:

ConjuntoPara qué¿Se usa para ajustar \( w \) y \( b \)?
Entrenamiento (train)calcular los gradientes y mover los parámetrossí
Validación (validation)comparar configuraciones (lr, épocas, nº de variables) y elegir la mejorno
Prueba (test)medir el resultado final, una sola vez, al acabarno

Imagina 60 películas con sus horas vistas: 40 sirven para entrenar, 20 se apartan para validar y, si hubiera conjunto de prueba, serían los estrenos que ni miras hasta el final. En PyTorch se parten con torch.utils.data.random_split(dataset, [40, 20]) (o con torch.randperm y los índices): devuelve subconjuntos barajados con los tamaños que pidas (y puedes pasarle un generator con semilla para que sea reproducible). El procedimiento: para cada learning rate candidato (en potencias de 10: 0,001, 0,01, 0,1…) entrenas con train, mides el coste en validation y te quedas con el que da menor coste de validación; el test ni se toca. En el fragmento 11 el ganador es \( lr = 0{,}2 \) con un MSE de validación de 0,0951, que además es casi el nivel del ruido de los datos (\( 0{,}3^2 = 0{,}09 \)): no se puede bajar de ahí.

Regla fácil

Prueba el learning rate en potencias de 10 con pocas épocas y mira la curva de coste: si sube o da NaN, baja el lr; si casi no se mueve, súbelo; si oscila, bájalo un poco. Elige por el coste de validación, no por el de entrenamiento. Con SGD suele funcionar entre 0,001 y 0,1; con las variables estandarizadas, mucho más fácil.

Ojo: una honestidad sobre este ejemplo

La regresión lineal tiene un solo mínimo y, con épocas suficientes, casi cualquier lr estable llega a él: la validación aquí solo elige «el que llega antes». Donde la validación es imprescindible es en las redes neuronales (siguientes módulos), donde el lr cambia a dónde llegas, no solo cuándo, y donde un modelo con muchos parámetros puede memorizar el entrenamiento mientras el coste de validación sube (sobreajuste). La mecánica de este apartado es la misma.

11 · Elegir el learning rate con validación

Para qué sirve Partir los datos con random_split, entrenar con varios learning rates y elegir el que da menor coste de validación; ver también cuándo diverge.

import torch
from torch import nn
from torch.utils.data import random_split

torch.manual_seed(0)
X = torch.arange(-3, 3, 0.1).view(-1, 1)
Y = -3 * X + 1 + 0.3 * torch.randn(X.size())
train_idx, val_idx = random_split(range(len(X)), [40, 20], generator=torch.Generator().manual_seed(7))
Xtr, Ytr = X[list(train_idx)], Y[list(train_idx)]
Xva, Yva = X[list(val_idx)], Y[list(val_idx)]
print("entrenamiento:", len(Xtr), " validación:", len(Xva))

def probar(lr, epocas=10):
    torch.manual_seed(1)
    model = nn.Linear(1, 1)
    opt = torch.optim.SGD(model.parameters(), lr=lr)
    crit = nn.MSELoss()
    for _ in range(epocas):
        loss = crit(model(Xtr), Ytr)
        opt.zero_grad(); loss.backward(); opt.step()
    with torch.no_grad():
        return crit(model(Xtr), Ytr).item(), crit(model(Xva), Yva).item()

print("lr        MSE entrenamiento   MSE validación")
resultados = {}
for lr in [0.001, 0.01, 0.05, 0.1, 0.2, 0.3, 0.4]:
    tr, va = probar(lr)
    resultados[lr] = va
    print(f"{lr:<8}  {tr:17.4f}   {va:14.4f}")
validos = {lr: v for lr, v in resultados.items() if v == v}     # descarta los nan
mejor = min(validos, key=validos.get)
print("mejor lr según validación:", mejor)
print("límite teórico de estabilidad 2 / (2 * media(x^2)) =", round(1 / (Xtr ** 2).mean().item(), 3))

16 · Entrenar, validar, probar, guardar el mejor modelo y cargarlo

Para qué sirve Partir los datos en train/validation/test, quedarse con la mejor época (checkpoint), guardar y cargar con state_dict, medir MSE y R² en test y ver por qué hace falta deepcopy.

import copy
import torch
from torch import nn

torch.manual_seed(0)
X = torch.randn(300, 3)
Y = (0.5 + X @ torch.tensor([[1.0], [-2.0], [0.5]])) + 0.5 * torch.randn(300, 1)
perm = torch.randperm(300)
tr, va, te = perm[:180], perm[180:240], perm[240:]          # 60 % / 20 % / 20 %
print("tamaños:", len(tr), len(va), len(te))

torch.manual_seed(1)
model = nn.Linear(3, 1)
crit = nn.MSELoss()
opt = torch.optim.SGD(model.parameters(), lr=0.05)
mejor_val, mejor_estado, mejor_epoca = float("inf"), None, -1
for epoch in range(1, 201):
    model.train()
    loss = crit(model(X[tr]), Y[tr])
    opt.zero_grad(); loss.backward(); opt.step()
    model.eval()
    with torch.no_grad():
        val = crit(model(X[va]), Y[va]).item()
    if val < mejor_val:
        mejor_val, mejor_epoca = val, epoch
        mejor_estado = copy.deepcopy(model.state_dict())     # copia independiente
    if epoch in (1, 10, 50, 200):
        print(f"época {epoch:3d}  train = {loss.item():.4f}  val = {val:.4f}")
print("mejor época:", mejor_epoca, " val =", round(mejor_val, 4))

torch.save(mejor_estado, "modelo_lineal.pt")                 # guardar solo los parámetros
nuevo = nn.Linear(3, 1)                                      # arquitectura vacía
nuevo.load_state_dict(torch.load("modelo_lineal.pt"))        # cargar los parámetros
nuevo.eval()
with torch.no_grad():
    pred = nuevo(X[te])
    mse = crit(pred, Y[te]).item()
    r2 = 1 - ((pred - Y[te]) ** 2).sum() / ((Y[te] - Y[te].mean()) ** 2).sum()
print("test: MSE =", round(mse, 4), " R² =", round(r2.item(), 4))
print("pesos cargados:", nuevo.weight.detach().numpy().round(3), nuevo.bias.detach().numpy().round(3))

ref = model.state_dict()                                     # SIN copiar: apunta a los mismos tensores
antes = ref["bias"].item()
with torch.no_grad():
    model.bias += 1.0
print("sin deepcopy el «guardado» cambia solo:", round(antes, 3), "->", round(ref["bias"].item(), 3))
