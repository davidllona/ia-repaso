Un Dataset solo responde dos preguntas: cuántas fichas hay y cuál es la i

Para PyTorch, «los datos» son cualquier objeto que sepa decir cuántas fichas tiene (len(ds)) y darte la ficha número i (ds[i]). Con eso basta.

Índice del módulo

Un catálogo de seis planes de cine: \( x = 0, 1, \dots, 5 \) amigos y \( y = 2x + 1 \) bolsas de palomitas. ¿Qué devuelve ds[4]? ¿Y ds[6]?

ds[4] devuelve (4, 9): 4 amigos, \( 2\cdot 4 + 1 = 9 \) bolsas. ds[6] lanza IndexError: los índices van de 0 a 5. Ese error no es un fallo: es la señal con la que Python sabe que se acabó el catálogo.

Un catálogo con tamaño y acceso por posición

Al catálogo de Netflix no le importa de qué va cada película ni en qué servidor está el vídeo. Solo responde a dos preguntas. Un Dataset propio es una clase con tres métodos:

class MiDataset(Dataset):
    def __init__(self, ...):   # UNA vez: guarda o localiza los datos
    def __len__(self):         # len(ds)  → cuántas muestras
    def __getitem__(self, i):  # ds[i]    → (entrada, etiqueta)

Tú nunca llamas a __len__ ni a __getitem__: los llama Python cuando escribes len(ds) o ds[i], y el DataLoader solo usa esas dos cosas.

La decisión importante es qué va en cada método. Una tabla pequeña se carga entera en __init__ y __getitem__ solo indexa. Miles de pósters en disco no: en __init__ se guarda la lista de rutas y cada póster se abre en __getitem__, solo cuando se pide (carga perezosa). Si tus datos ya son tensores, ni siquiera hace falta la clase: TensorDataset(X, y) devuelve (X[i], y[i]).

Y cuida los tipos: entradas en float32 (el tipo de los pesos), etiquetas de regresión en float32 y etiquetas de clase en int64.

Con números: estandarizar los minutos

Ejemplo numérico · la primera ficha del CSV, z = 1,6807

La columna «minutos» de las 8 películas del CSV: 108, 91, 81, 61, 64, 43, 46 y 41.

  1. Media: suman 535, así que \( \mu = 535/8 = 66{,}875 \).
  2. Desviación (muestral, entre \( n-1 = 7 \)): los cuadrados de las diferencias suman 4190,875; \( 4190{,}875/7 = 598{,}696 \) y \( \sigma = 24{,}468 \).
  3. Primera ficha: \( z = (108 - 66{,}875)/24{,}468 = \) 1,6807, justo lo que devuelve ds[0].

En un proyecto real, \( \mu \) y \( \sigma \) salen solo del entrenamiento; si no, hay fuga de datos.

Un millón de pósters de 224 × 224 × 3 en float32. ¿Los cargas todos en __init__?

No caben. Cada póster ocupa \( 224\cdot 224\cdot 3\cdot 4 = 602\,112 \) bytes (0,6 MB): el millón son unos 602 GB. Se guardan las rutas y cada póster se abre en __getitem__. En cambio MNIST (60 000 × 784 × 4 bytes ≈ 188 MB) sí cabe en memoria.

En tres líneas

  • Un Dataset es una colección con __len__ (cuántas) y __getitem__ (la ficha i).
  • Lo pequeño se carga en __init__; lo grande se abre en __getitem__ (carga perezosa).
  • Entradas float32, clases int64; TensorDataset si ya tienes tensores.

La clase Dataset: un catálogo numerado

¿Qué tiene que saber hacer un objeto para que PyTorch pueda usarlo como «los datos» de un modelo? ¿Y cómo se escribe uno propio, por ejemplo para el catálogo de películas de una plataforma (una tabla, unos pósters o lo que sea)?

Analogía

El catálogo de Netflix, con una ficha numerada por título. El catálogo solo tiene que responder a dos preguntas: «¿cuántos títulos hay?» y «dame la ficha número i». No le importa de qué trata cada película, ni en qué servidor está guardado el vídeo, ni si hay que ir a buscar el póster a otro sitio. Un Dataset de PyTorch es exactamente eso: una colección con tamaño y acceso por posición.

Las tres piezas de un Dataset

from torch.utils.data import Dataset

class MiDataset(Dataset):            # 1. hereda de Dataset
    def __init__(self, ...):         #    se ejecuta UNA vez: guarda o localiza los datos
        ...
    def __len__(self):               # 2. cuántas muestras hay      → len(ds)
        return ...
    def __getitem__(self, i):        # 3. la muestra número i       → ds[i]
        return entrada, etiqueta
  1. __init__ es el constructor: recibe lo que necesites (una ruta, un tensor, una transformación) y lo guarda en self. Se ejecuta una vez, al crear el dataset.
  2. __len__ devuelve el número de muestras. Python lo llama cuando escribes len(ds). El DataLoader lo necesita para repartir los índices y saber cuándo acaba una época.
  3. __getitem__ recibe un índice entero \( i \) (de 0 a \( N-1 \)) y devuelve la muestra \( i \): normalmente un par (entrada, etiqueta). Python lo llama cuando escribes ds[i].

Los nombres con doble guion bajo (__len__, __getitem__) son los métodos especiales de Python: no los llamas tú directamente, es Python quien los llama cuando usas len(...) o los corchetes. Por eso basta con definirlos para que tu objeto se comporte como una colección. Además, PyTorch los llama así: el DataLoader solo necesita len(ds) y ds[i].

Ejemplo numérico · el dataset de juguete \( y = 2x + 1 \)

Imagina seis planes de cine en casa (cifras inventadas): la entrada es \( x = 0, 1, \dots, 5 \) amigos que vienen a ver la peli y la etiqueta es \( y = 2x + 1 \) bolsas de palomitas (dos por amigo y una para ti). El dataset del fragmento 1 tiene exactamente esas seis fichas y responde así:

LlamadaQué ejecutaResultado
len(ds)ds.__len__()6
ds[0]ds.__getitem__(0)(0, 1) porque \( 2\cdot 0 + 1 = 1 \): vas tú solo, 1 bolsa
ds[4]ds.__getitem__(4)(4, 9) porque \( 2\cdot 4 + 1 = 9 \): 4 amigos, 9 bolsas
ds[6]ds.__getitem__(6)IndexError: no hay ficha 6 (los índices llegan a 5)

Qué va en __init__ y qué en __getitem__

Esta decisión es la más importante al diseñar un dataset:

  • Datos pequeños que caben en memoria (una tabla, los dígitos de scikit-learn): se cargan una vez en __init__ y __getitem__ solo indexa. Es lo más rápido.
  • Datos grandes (miles de imágenes en disco): en __init__ solo se guarda la lista de rutas; la imagen se abre en __getitem__, solo cuando se pide. Es la carga perezosa (lazy loading).
Ejemplo numérico · ¿cabe en memoria?

Un conjunto pequeño, MNIST (dígitos escritos a mano): 60 000 imágenes de \( 28\times 28 \) píxeles en float32 (4 bytes cada número) ocupan \( 60\,000 \cdot 784 \cdot 4 = 188\,160\,000 \) bytes ≈ 188 MB: sin problema. Ahora el catálogo de pósters de una plataforma (cifra inventada: 1 000 000 de pósters): cada póster de \( 224\times 224\times 3 \) en float32 ocupa \( 224\cdot 224\cdot 3\cdot 4 = 602\,112 \) bytes (≈ 0,6 MB), así que el millón ocupa ≈ 602 GB. Eso no cabe en la memoria de ningún ordenador normal, así que el dataset tiene que abrir cada póster cuando se lo piden. Con la carga perezosa, en memoria solo hay lo que se está usando.

El Dataset más sencillo: TensorDataset

Si tus datos ya son tensores del mismo tamaño en la primera dimensión, no hace falta escribir una clase: TensorDataset(X, y) hace exactamente lo que acabas de ver (ds[i] devuelve (X[i], y[i])) y comprueba que X e y tienen el mismo número de filas (fragmento 2). Lo usarás mucho en este curso para datos sintéticos.

Un Dataset a partir de un CSV

El caso más habitual en datos tabulares: los datos están en un archivo CSV (por ejemplo, una ficha por título con su duración, el número de actores famosos, los años desde el estreno y las visualizaciones). Se leen con pandas en __init__, se convierten a tensores y __getitem__ devuelve la fila (fragmento 3). Pensando ya en el entrenamiento hay dos reglas: las entradas se convierten a float32 (el tipo que esperan los modelos) y, en regresión, la etiqueta también y con forma (1,) por muestra.

Aparece aquí la primera transformación: estandarizar las columnas para que tengan media 0 y desviación 1, con la fórmula \( z = (x-\mu)/\sigma \). Con la columna «minutos» de los 8 títulos del fragmento: los valores son 108, 91, 81, 61, 64, 43, 46 y 41, la suma es 535 y la media \( \mu = 535/8 = 66{,}875 \). Las desviaciones respecto a la media son \( 41{,}125;\ 24{,}125;\ 14{,}125;\ -5{,}875;\ -2{,}875;\ -23{,}875;\ -20{,}875;\ -25{,}875 \); sus cuadrados suman \( 4190{,}875 \); dividiendo entre \( 8-1=7 \) (PyTorch usa la desviación muestral, con \( n-1 \)) sale la varianza \( 598{,}696 \) y \( \sigma = \sqrt{598{,}696} = 24{,}468 \). Entonces la primera ficha (108 minutos) queda en \( (108 - 66{,}875)/24{,}468 = 1{,}6807 \), el número que imprime el fragmento.

Experimento de arriba: «ds[i] y len(ds) sobre un catálogo de 8 películas», con todo detalle

Haz esto. Mueve «índice i en ds[i]» de 0 a 9 y mira qué ficha del catálogo se resalta y qué devuelve ds[i]. Activa «transform = estandarizar» y compara el primer número de ds[0] con la cuenta que acabas de leer (1,6807). Por último, pon i = 8 y i = 9.

Fíjate en. Cada ds[i] devuelve el par (entradas, etiqueta) de una ficha (una fila); la transformación solo toca las entradas y se aplica en el momento de pedir la muestra, no antes: la tabla guardada no cambia. Con i = 8 o 9 no hay ficha y salta IndexError, justo la señal con la que Python (y el DataLoader) saben cuándo parar.

Ojo · calcula las estadísticas solo con entrenamiento

En el fragmento se calculan la media y la desviación con todo el catálogo de 8 películas porque es un ejemplo. En un proyecto real, media y desv se calculan únicamente con los datos de entrenamiento y se reutilizan tal cual con validación y prueba. Si usaras también la validación estarías dejando que información de ella se cuele en el modelo: es la fuga de datos (data leakage, Curso 1, módulo 5).

Qué puede devolver __getitem__ y con qué tipos

Casi siempre un par (entrada, etiqueta), pero puede ser un diccionario ({"x": …, "id": …}), una tupla de tres cosas o un único tensor (datos sin etiqueta). El DataLoader sabe apilar todo eso (fragmento 16). Lo que sí importa son los tipos de los tensores, porque el modelo y la pérdida los exigen:

DatoTipo habitualPor qué
Entradas (características, píxeles)torch.float32Es el tipo de los pesos del modelo; mezclar float32 y float64 da error (fragmento 22).
Etiqueta de regresióntorch.float32, forma como la salidaLa pérdida (MSE) resta salida y etiqueta.
Etiqueta de clasificación (clase 0, 1, 2…)torch.int64 (long)CrossEntropyLoss usa la etiqueta como un índice (Módulo 5).

Datasets «de flujo»: IterableDataset

Lo que hemos visto es un dataset de estilo mapa (map-style): asocia cada índice con una muestra. Existe otro tipo, IterableDataset, que en lugar de __getitem__ define __iter__ y solo sabe entregar «el siguiente». Sirve para flujos de datos (un archivo gigantesco que se lee de principio a fin, datos que llegan de la red). Como no sabe su longitud ni puede dar la muestra 3 sin pasar por la 0, 1 y 2, no admite len ni shuffle=True (fragmento 4). En este curso usaremos casi siempre datasets de estilo mapa.

Código

1 · Un Dataset propio, mínimo

Para qué sirve Crear tu propia clase Dataset con los tres métodos obligatorios (__init__, __len__, __getitem__) y comprobar que se comporta como una colección numerada: se le pide el tamaño, se saca la muestra i y se puede recorrer con for.

import torch
from torch.utils.data import Dataset

class ConjuntoJuguete(Dataset):
    def __init__(self, n=6):
        self.x = torch.arange(n, dtype=torch.float32).reshape(n, 1)
        self.y = 2 * self.x + 1
        self.n = n

    def __len__(self):
        return self.n

    def __getitem__(self, indice):
        return self.x[indice], self.y[indice]

ds = ConjuntoJuguete()
print("len(ds)       :", len(ds))
print("ds[0]         :", ds[0])
print("ds[4]         :", ds[4])
x3, y3 = ds[3]
print("desempaquetado:", x3.item(), "->", y3.item())
print("recorrido     :", [(x.item(), y.item()) for x, y in ds])
try:
    ds[6]
except IndexError as error:
    print("ds[6] falla   :", type(error).__name__)

3 · Un Dataset a partir de un CSV con pandas

Para qué sirve Leer una tabla de títulos guardada en un archivo CSV, convertirla en tensores float32 y servirla muestra a muestra, con una transformación opcional (aquí, estandarizar las características) aplicada al sacar cada fila.

Para que el fragmento funcione sin archivos externos, primero fabrica una tabla de 8 títulos del catálogo (películas y capítulos) con datos sintéticos inventados (semilla fija) y la guarda como peliculas.csv en una carpeta temporal.

import os, tempfile
import numpy as np
import pandas as pd
import torch
from torch.utils.data import Dataset

rng = np.random.default_rng(0)
n = 8
tabla = pd.DataFrame({
    "minutos": rng.integers(40, 121, n),
    "actores": rng.integers(1, 5, n),
    "anios": rng.integers(0, 41, n),
})
tabla["vistas"] = 2.0 * tabla["minutos"] + 10 * tabla["actores"] - 1.5 * tabla["anios"] + 20
ruta = os.path.join(tempfile.mkdtemp(), "peliculas.csv")
tabla.to_csv(ruta, index=False)
print(tabla.head(3).to_string())

class PeliculasCSV(Dataset):
    def __init__(self, ruta, transform=None):
        datos = pd.read_csv(ruta)
        self.x = torch.tensor(datos[["minutos", "actores", "anios"]].values, dtype=torch.float32)
        self.y = torch.tensor(datos["vistas"].values, dtype=torch.float32).unsqueeze(1)
        self.transform = transform

    def __len__(self):
        return len(self.x)

    def __getitem__(self, i):
        x, y = self.x[i], self.y[i]
        if self.transform is not None:
            x = self.transform(x)
        return x, y

ds = PeliculasCSV(ruta)
print("len(ds):", len(ds))
print("ds[0]  :", ds[0])

media, desv = ds.x.mean(dim=0), ds.x.std(dim=0)
def estandarizar(x):
    return (x - media) / desv

ds_norm = PeliculasCSV(ruta, transform=estandarizar)
print("media por columna      :", [round(v, 3) for v in media.tolist()])
print("desviación por columna:", [round(v, 3) for v in desv.tolist()])
print("ds_norm[0]            :", ds_norm[0])
todas = torch.stack([ds_norm[i][0] for i in range(len(ds_norm))])
print("media tras estandarizar ≈ 0:", bool(todas.mean(dim=0).abs().max() < 1e-6))
print("desviación tras estandarizar:", todas.std(dim=0))
