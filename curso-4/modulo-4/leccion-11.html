Errores típicos, con los mensajes reales

Cuando algo falla en PyTorch, ¿qué está pasando casi siempre y cómo se arregla?

El fragmento 19 provoca ocho errores a propósito y copia los mensajes que devuelve la versión instalada (PyTorch 2.14.1). Los siete primeros son excepciones; el octavo no avisa de nada, y por eso es el más peligroso.

Qué hacesQué pasaPor qué y cómo se arregla
1. Pasas logits a BCELossRuntimeError: all elements of input should be between 0 and 1BCELoss espera probabilidades. Aplica torch.sigmoid o cambia a BCEWithLogitsLoss.
2. Etiquetas enteras (long) en BCELossRuntimeError: Found dtype Long but expected FloatLa etiqueta debe ser decimal: y.float() o dtype=torch.float32.
3. Predicción de forma (N,) y etiqueta (N,1)ValueError: Using a target size (torch.Size([3, 1])) that is different to the input size (torch.Size([3])) is deprecated…Las formas deben coincidir: .reshape(-1, 1) o .flatten() en las dos.
4. Entrada entera en nn.LinearRuntimeError: mat1 and mat2 must have the same dtype, but got Long and FloatLos pesos son float32 y la entrada long: crea el tensor con puntos decimales o con dtype=torch.float32.
5. Entrada 1D (3,) en nn.Linear(1,1)RuntimeError: mat1 and mat2 shapes cannot be multiplied (1x3 and 1x1)PyTorch la leyó como una muestra con 3 variables. Hace falta una columna (N, 1): .reshape(-1, 1).
6. Etiquetas enteras en BCEWithLogitsLossRuntimeError: result type Float can't be cast to the desired output type LongMismo problema que el 2, con otro mensaje. y.float().
7. Olvidar super().__init__()AttributeError: cannot assign module before Module.__init__() callEn un nn.Module la primera línea del __init__ debe ser super().__init__().
8. nn.Sigmoid() en el modelo y BCEWithLogitsLossNingún error. Pérdida 0.5932 (en vez de 0.3598) y pesos \( w=1.377,\ b=-6.070 \).La sigmoide se aplica dos veces. Una sigmoide con BCELoss, o ninguna con BCEWithLogitsLoss.
Ojo · otros tropiezos frecuentes
  • Olvidar zero_grad(): los gradientes se acumulan y el modelo se comporta de forma incoherente (la pérdida no baja bien aunque no haya ningún error).
  • Predecir con (p == y) en vez de con el umbral (ver «Evaluar»).
  • Usar model(x).numpy() con un modelo que requiere gradiente: da error («Can't call numpy() on Tensor that requires grad»). Usa with torch.no_grad(): o .detach().numpy().
  • Evaluar sobre los datos de entrenamiento y creer que esa es la nota real.
  • Confundir logits con probabilidades al interpretar: un logit de 0.28 no es «28 %»; es \( p=0.57 \).
  • Olvidar estandarizar variables de escalas muy distintas.
Regla fácil · cuando algo no cuadra, imprime las formas y los tipos

La mayoría de los errores de formas y tipos se resuelven mirando x.shape y x.dtype de lo que entra y de lo que sale. Entradas float32 con forma (N, n_variables); etiquetas float32 con forma (N, 1); salida del modelo con la forma de las etiquetas.

20 · Guardar el modelo y predecir con datos nuevos

Para qué sirve Guardar los parámetros entrenados, cargarlos en un modelo nuevo y escribir una función predecir que devuelva probabilidad y clase, que es lo que harías al «poner en producción» el modelo.

import io

buffer = io.BytesIO()
torch.save(logit_model.state_dict(), buffer)
buffer.seek(0)

nuevo = nn.Linear(1, 1)
nuevo.load_state_dict(torch.load(buffer, weights_only=True))
nuevo.eval()

def predecir(modelo, x, umbral=0.5):
    with torch.no_grad():
        p = torch.sigmoid(modelo(torch.as_tensor(x, dtype=torch.float32).reshape(-1, 1)))
    return p.flatten(), (p >= umbral).int().flatten()

p, clase = predecir(nuevo, [1.0, 3.0, 3.76, 5.0, 8.0])
for d, pi, ci in zip([1.0, 3.0, 3.76, 5.0, 8.0], p.tolist(), clase.tolist()):
    print(f"{d:4.2f} días -> p = {pi:.3f} -> clase {ci}")
print("claves guardadas:", list(logit_model.state_dict().keys()))
