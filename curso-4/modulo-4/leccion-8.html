Dos variables: la frontera es una recta (y por qué hay que estandarizar)

Si cada usuario tiene dos números (días sin abrir la app y, por ejemplo, series abandonadas a medias este mes), ¿cómo cambia el modelo y dónde está ahora «la frontera»?

Analogía

Con una variable, la frontera era un punto en una línea (los 3.76 días): a un lado «se queda», al otro «cancela». Con dos variables el terreno es un mapa plano (días sin abrir × series abandonadas) y la frontera es una valla recta que lo parte en dos regiones. Con tres variables sería un plano; con \( n \), un hiperplano.

El modelo con dos entradas

Solo cambia el primer argumento: nn.Linear(2, 1). Ahora weight tiene forma (1, 2) (una fila con \( w_1 \) y \( w_2 \)) y bias sigue siendo (1,). La entrada es una matriz (N, 2), una columna por variable. El modelo calcula \( z = w_1x_1 + w_2x_2 + b \) y \( p = \sigma(z) \). La frontera es el conjunto de puntos con \( p = 0.5 \), es decir, \( z = 0 \):

\[ w_1 x_1 + w_2 x_2 + b = 0 \quad\Longrightarrow\quad x_2 = -\frac{w_1 x_1 + b}{w_2} \]

Es la ecuación de una recta con pendiente \( -w_1/w_2 \) que corta el eje \( x_2 \) en \( -b/w_2 \). El vector \( (w_1, w_2) \) es perpendicular a la recta y apunta hacia el lado de la clase 1.

Estandarizar las variables

Si una variable va de 0 a 10 (días sin abrir la app) y otra de 0 a 1000 (segundos de buffering en el último mes), el gradiente de la segunda es unas 100 veces mayor, y el paisaje de la pérdida es un valle estrecho y alargado en el que el descenso del gradiente rebota. La solución estándar es la estandarización (z-score):

\[ x' = \frac{x - \mu}{\sigma} \]

donde \( \mu \) y \( \sigma \) son la media y la desviación típica de cada columna, calculadas solo con los datos de entrenamiento (y aplicadas igual a validación y a datos futuros, para no «hacer trampas» con información que el modelo no debería conocer). Tras esto cada variable tiene media 0 y desviación 1. En PyTorch: media, desv = X.mean(0), X.std(0) y X_esc = (X - media) / desv.

Ojo · estandariza con las estadísticas de entrenamiento

Calcula \( \mu \) y \( \sigma \) con X_tr y guárdalas. Si el día de mañana llega un usuario nuevo, hay que aplicarle esas mismas \( \mu \) y \( \sigma \), no las de sus datos. Y recuerda que X.std(0) usa por defecto la desviación corregida (divide por \( N-1 \)); la diferencia es mínima con muchos datos, pero conviene ser consistente.

15 · Dos variables: nn.Linear(2, 1) y la frontera como recta

Para qué sirve Entrenar una regresión logística con dos variables y leer la frontera \(w_1x_1+w_2x_2+b=0\) a partir de los pesos.

g = torch.Generator().manual_seed(3)
n = 100
se_quedan = torch.randn(n, 2, generator=g) * 0.8 + torch.tensor([2.0, 2.0])
cancelan = torch.randn(n, 2, generator=g) * 0.8 + torch.tensor([4.0, 3.5])
X = torch.cat([se_quedan, cancelan])
y = torch.cat([torch.zeros(n, 1), torch.ones(n, 1)])

orden = torch.randperm(2 * n, generator=g)
X, y = X[orden], y[orden]
X_tr, y_tr, X_va, y_va = X[:150], y[:150], X[150:], y[150:]
print("X_tr:", tuple(X_tr.shape), " y_tr:", tuple(y_tr.shape))

torch.manual_seed(0)
modelo = nn.Linear(2, 1)
criterio = nn.BCEWithLogitsLoss()
opt = torch.optim.SGD(modelo.parameters(), lr=0.1)
for epoca in range(1000):
    loss = criterio(modelo(X_tr), y_tr)
    opt.zero_grad(); loss.backward(); opt.step()

w1, w2 = modelo.weight[0].tolist()
b = modelo.bias.item()
print(f"w1 = {w1:.3f}  w2 = {w2:.3f}  b = {b:.3f}  pérdida = {loss.item():.4f}")
print(f"frontera: {w1:.3f}·x1 + {w2:.3f}·x2 {b:+.3f} = 0")
for x1 in (1.0, 3.0, 5.0):
    print(f"  si x1 = {x1}: x2 = {-(w1 * x1 + b) / w2:.3f}")

with torch.no_grad():
    acc_tr = ((modelo(X_tr) > 0).float() == y_tr).float().mean().item()
    acc_va = ((modelo(X_va) > 0).float() == y_va).float().mean().item()
    p_nuevo = torch.sigmoid(modelo(torch.tensor([[3.0, 2.5]]))).item()
print(f"accuracy train {acc_tr:.3f}   validación {acc_va:.3f}")
print(f"punto (3.0, 2.5): p = {p_nuevo:.3f}")

17 · Escalar las variables: estandarizar antes de entrenar

Para qué sirve Comprobar con una variable de 0 a 10 y otra de 0 a 1000 que, sin escalar, el mismo modelo no aprende bien con ninguno de los learning rates que probamos; y estandarizar (media 0, desviación 1) lo arregla.

g = torch.Generator().manual_seed(5)
n = 200
sin_abrir = torch.rand(n, 1, generator=g) * 10
buffering = torch.rand(n, 1, generator=g) * 1000
z_real = 0.9 * (sin_abrir - 5) + 0.01 * (buffering - 500)
y = (torch.rand(n, 1, generator=g) < torch.sigmoid(z_real)).float()
X = torch.cat([sin_abrir, buffering], dim=1)
print("mínimo de cada columna:", X.min(0).values.numpy().round(1), " máximo:", X.max(0).values.numpy().round(1))

media, desv = X.mean(0), X.std(0)
X_esc = (X - media) / desv
print("tras estandarizar: media", X_esc.mean(0).numpy().round(3), " desv", X_esc.std(0).numpy().round(3))

def entrenar(Xd, lr, epocas=300):
    torch.manual_seed(0)
    m = nn.Linear(2, 1)
    opt = torch.optim.SGD(m.parameters(), lr=lr)
    for e in range(epocas):
        loss = nn.BCEWithLogitsLoss()(m(Xd), y)
        opt.zero_grad(); loss.backward(); opt.step()
    acc = ((m(Xd) > 0).float() == y).float().mean().item()
    return m, loss.item(), acc

for nombre, Xd in (("sin escalar", X), ("estandarizadas", X_esc)):
    for lr in (0.00001, 0.001, 0.1):
        m, loss, acc = entrenar(Xd, lr)
        print(f"{nombre:15s} lr={lr:<6}: pérdida {loss:9.4f}  accuracy {acc:.3f}")
