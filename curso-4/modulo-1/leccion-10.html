NumPy, Pandas y PyTorch: pasar de uno a otro

Tus datos (por ejemplo, el historial de lo que ha visto cada usuario) llegan en una tabla de Pandas o en un array de NumPy. ¿Cómo los conviertes en tensores, cómo vuelves a NumPy para dibujar o guardar, y qué pasa con la memoria al hacerlo?

Analogía

Una lista de reproducción de Netflix. torch.from_numpy(arr) no crea una lista nueva: es como compartir la misma lista con otra persona. Si ella añade o quita una película, tú lo ves al instante, porque es la misma lista. torch.tensor(arr), en cambio, hace una copia de la lista: es otra lista con sus propias películas, y los cambios en una no afectan a la otra.

Ojo · NumPy usa float64 y PyTorch espera float32

np.array([1.0, 2.0]) es float64, así que torch.from_numpy te da un tensor float64. Cuando más adelante lo pases por una capa nn.Linear (que guarda sus pesos en float32), recibirás un error de tipo («mat1 and mat2 must have the same dtype»). Haz siempre torch.tensor(arr, dtype=torch.float32) o .float(). El fragmento 12 muestra los tres casos (comparten, copian, cambian de tipo).

De Pandas a tensor

Un DataFrame de Pandas no se convierte directamente: se pasa por su array de NumPy. El patrón para un problema de aprendizaje supervisado es: las columnas de entrada a un tensor float32 de forma (muestras, características) y la columna de etiquetas a otro tensor (int64 si son clases, float32 si es un valor numérico a predecir):

X = torch.tensor(df[["capitulos", "fraccion_ultimo"]].values, dtype=torch.float32)   # (5, 2)
y = torch.tensor(df["termino_serie"].values)                                      # (5,)  int64

Ojo · Pandas 3 y los arrays de solo lectura

Con Pandas 3, df['col'].to_numpy() devuelve a veces un array de solo lectura. Si lo pasas a torch.from_numpy (que comparte memoria), PyTorch emite un UserWarning: The given NumPy array is not writable…: escribir en ese tensor podría estropear la tabla. Para evitarlo, usa torch.tensor(…), que copia, como hace el fragmento 13.

12 · NumPy ↔ PyTorch: qué comparte memoria y qué se copia

Para qué sirve Pasar de un array de NumPy a un tensor y viceversa, comprobar quién comparte memoria con quién y ver el detalle del float64 que NumPy mete por defecto.

import numpy as np
import torch

arr = np.array([1.0, 2.0, 3.0])
t = torch.from_numpy(arr)
c = torch.tensor(arr)
print(t, t.dtype)

t[0] = 100.0
print("arr tras tocar t:", arr)
print("c   (copia)     :", c)
back = t.numpy()
arr[1] = -5.0
print("back:", back, "| t:", t)

enteros = np.array([1, 2, 3])
print(enteros.dtype, torch.from_numpy(enteros).dtype)
t32 = torch.tensor(arr, dtype=torch.float32)
print(t32.dtype, torch.from_numpy(arr.astype(np.float32)).dtype)
print(torch.tensor([1.0, 2.0]).dtype, torch.tensor(np.array([1.0, 2.0])).dtype)

Tras t[0] = 100.0, arr es [100., 2., 3.] (comparten memoria) pero la copia c sigue en [1., 2., 3.]. Luego arr[1] = -5 aparece en t y en back. El detalle que más molesta después: np.array([1.0, 2.0]) es float64 y por tanto el tensor también (torch.float64), mientras que una lista de Python da float32. Las capas de PyTorch usan float32; si les das float64 aparecen errores de tipo («mat1 and mat2 must have the same dtype»). La receta: torch.tensor(arr, dtype=torch.float32) o torch.from_numpy(arr.astype(np.float32)).
